# 多张图并行的研究目标与下一步准入条件

> 2026-10-20 后续目标已调整：不要求独立多图独有收益，
> 优先研究固定图消费动态描述符的算子优化，不增路由器、不扩完整模型。
> 本文保留为历史证据；当前以[最新目标](aclgraph_multigraph_research_goal_zh.md)
> 和[动态描述符方案](aclgraph_dynamic_descriptor_plan_zh.md)为准。

日期：2026-10-20。根据用户最新要求，主线是寻找多张 ACLGraph 独立并行回放的价值；
已有大矩阵通算融合方向可以继续，但作为辅助路线，不替代主线。

**可直接使用的研究目标：** 深入分析动态 shape 下多张 ACLGraph 独立调度、并行回放
与动态组合的优势，寻找能改变完整 step 关键路径、具有明确净收益来源的结构性方案，
在默认捕获容量和常规动态 batch 下争取超过同等优化的 Padding。
先复用历史 profiling、源码和相关工作筛选，说明为何需要多图、单图可否等效表达、
减少什么等待以及增加什么成本；形成包含依赖、状态生命周期、多卡通信次序、
资源预算、适用范围、失败条件和最小验证的中文方案后，先汇报，再深入实现。
验证包括 Padding、多图串行、多图并行及同依赖的组合单图，全部真实工作均计时。
公共融合单独归因，不预设多图必然胜出；没有可信净收益路线时如实说明，继续收紧或调整方案。

第一阶段已完成证据审查、历史原始报告复算与候选方案细化，见
[多图第一阶段分析与验证计划](aclgraph_multigraph_stage1_analysis_zh.md)。
目前尚无足够证据支持可大幅超过同等优化 Padding 的多图方案；
下一门槛是证明不同动态状态存在有用的方案排名变化和至少一个净胜状态。

新增[完整路径更新等待核查](aclgraph_fia_update_critical_path_zh.md)：
两层约 0.5 ms 的 FIA 等待未在已有完整模型样本重现；组合图互斥共享池也有匹配源码支持。
不能以局部等待外推或未经测量的图内存困难，作为独立多图的大收益依据。

新增[生产/消费协议与强基线预算](aclgraph_multigraph_producer_consumer_contract_zh.md)：
公开 Down/RS 的内部列带进度不等于 Norm 所需的完整行就绪，也未证明有外部消费者资源。
等待完整普通 Down 再行流水，会失去部分公共融合收益；历史 profile 的条件线性模型
只有约 59～63 μs 的流体理想余额，有限双组仍不及融合清单。该数字不是实测加速或通用上界。
下一候选须保留融合生产者、闭合数据与核心进度，并通过完整端点预算，不能直接加多图 flag。

## 1. 先纠正证据的归属

最近 `aclgraph_bounded_lead_probe.py` 的完整两层实验，为每个 mode 捕获一张图，
在该图内安排请求分段、通信流和计算流。不同 mode 的图依次计时，不是同时回放。
因此该实验中的提前消费收益证明了依赖调度有价值，不能证明多张图独立回放更优。

此前工程里确实有独立多图执行器，但其存在也不能代替性能证据。
需区分三个对象：请求切分、单图内部多流、多张图独立回放。
今后报告必须明确被测对象，不能统称“切分并行”后混用结论。

## 2. 什么才算符合主线的结果

对同一批请求、同一数值路径和相同公共融合能力，需要区分以下对照。

| 对照 | 目的 |
| --- | --- |
| 整批 Padding | 检验最终是否有实用收益 |
| 多图串行 | 记录图切分、多个 replay 和布局整理的成本 |
| 多图并行 | 测量多个独立图之间的并行价值 |
| 同样分段和流依赖的组合单图 | 排除“只是单图内部也可做到的流水” |

多图并行优于多图串行，只能证明重叠有效；还需优于 Padding 才有净收益。
若与组合单图相当，固定组合的计算延迟收益应归为分段调度，而不是图数量。

多图的另一种潜在价值是有限捕获预算下的动态组合：独立图可以按当前请求情况组合，
不必为每个组合预捕获一张图。这属于缓存与适应性价值，不能冒充并行计算优势。
必须分别报告图内存、捕获开销、动态轨迹回放耗时；两种证据都成立时，才形成完整方案。

不能承诺任何多图调度都无法在一个足够灵活的单图系统中表达。
研究应明确所用运行时、固定图拓扑和捕获预算约束，而不是宣称无条件的独占性。

## 3. 主线候选：动态组合的独立执行单元

首先审查既有图目录与历史数据：是否存在满足默认容量、完整请求边界的组合，
其子图在真实工作负载下资源需求不同，能通过独立调度缩短整个 step。
例如 KV 工作量差异可能改变 attention 的耗时，但这本身不证明资源互补；
不能仅按长短 KV 就预言并行收益，必须看 trace 中真实未覆盖的资源窗口。

相较于再次均分两个相同小矩阵，更值得分析的自由度是：
本步选择哪些已有子图、各自何时提交、允许领先到哪里、何时汇合。
共享大矩阵边界可以保留，但若所有收益均来自共享段内部融合，主线依然不成立。

第一步只用历史证据筛选，不新增大实验矩阵：

1. 标出旧实验哪些是真正独立 graph replay，哪些只是组合单图内部多流。
2. 选出一个存在资源互补证据的合法图对；没有证据则继续 profiling，不直接测全模型。
3. 为同一图对写出组合单图对照的依赖，确保没有人为给单图增加全局等待。
4. 只做该图对的一次闭合段对照；全部提交、真实长度 update、状态写回和最终 join 均计时。

若组合单图可达到同样时延，就把后续问题限定为动态图组合的预算优势。
即使组合更省内存，如果没有动态 step 性能收益，也不能回答用户希望超过 Padding 的目标。
不通过制造不真实的请求到达时间、改变默认 capture sizes 或省略 update 获得优势。

## 4. 本轮源码审查已排除一个伪新方向

`UpdatableGraph.register_task` 已用 ExternalEvent 在图内等待对应 task 更新。
`ACLGraphWrapper._updatable_graph_replay` 的非 ENPU 分支先 replay、后提交更新，
不是必须等全部 host 更新结束才能开始整图执行。
已有 `NPUExecutionBackend.update_interleaved` 也已支持按 task 交错更新不同图。

因此“先让图 A 开跑，同时更新图 B”不能直接称为新机制，更不能假定单图完全不能重叠 update。
多图独立池、独立缓冲和生命周期事件也已有实现；继续工作要针对已测缺口，而不是重新实现这些组件。
代码存在不代表任意交错在多卡下都安全：collective 次序、task handle、状态和缓冲复用仍需逐项闭合。

## 5. 辅助路线：一次大 Down/RS 后的局部 Norm 与 AG/MM

本轮通过 SSH 对安装包做了只读接口核查，`npu_all_gather_base_mm` 存在。
安装版本、接口说明与 schema 保存在 [安装包接口快照](aclgraph_agmm_installed_interface.json)。
其安装包说明描述了 AllGather 与 Matmul 融合，并列出 BF16、AIV 下 NZ 权重以及 A2 场景。
这只是接口说明，不代表当前驱动、模型形状与手工 ACLGraph 已通过实测。
说明中的图模式示例使用 torchair，不能直接当成 NPUGraph 捕获资格证明。

同一说明还限定 A2 模型内通算融合使用相同通信域。
因此不能直接用多个独立融合通信域给两个图消除 collective 排队，需先满足该约束。
公开签名没有暴露外部逐请求行完成事件，不能拿未完成输出直接交给另一个图。

后续辅助实验必须计入两个 GDN 输入投影、Norm 输出 residual 的恢复及状态合批。
可先让 AG/MM 返回 gathered hidden 给第二个投影使用，以避免重复 gather，
但是否符合真实布局、是否有净收益仍需验证；不得省略 residual 的独立恢复成本。
这一接口即便有效，也同时提供给 Padding，并单列为公共优化。

## 6. 当前决策与停止条件

- 主线：先审查真正多图实验的历史证据，寻找独立回放可利用的资源窗口与动态组合价值。
- 辅线：继续完成大矩阵融合的数据依赖与接口资格核查，不将其收益写成多图贡献。
- 不把固定调度换成两个 graph handle 就称为新算法。
- 若图切分成本超过重叠窗口，停止该具体组合；不靠扩大 batch 或更稀疏容量制造结论。
- 本轮只有源码和接口核查，没有新性能结果，也尚未找到已证实能大幅超过 Padding 的多图方案。
