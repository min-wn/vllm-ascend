# 多张 ACLGraph 并行：第一阶段证据审查与候选方案

日期：2026-10-20。源码基线：`9aa464f9a`。本轮只做文献阅读、源码核查、
历史报告复算和默认容量穷举，没有启动新的 NPU 性能实验。

## 1. 本阶段的判断

**目前尚未找到有充分证据支持、可在当前默认 Q4 动态轨迹下大幅超过同等优化 Padding 的多图路线。**
继续增加并行流或改为两个 graph handle，不能解决已测到的矩阵拆小成本。

仍可研究的主线是：**在有限捕获资源下，按本步真实请求情况，组合和调度可复用的独立图，
让不同执行方案只在适合自己的动态状态下运行。**
这条线必须先证明“不同状态确实需要不同的最优方案，且至少有一类状态的多图方案超过 Padding”。
如果所有状态都是同一张 Padding 图最好，路由器没有收益来源；如果一个固定组合始终最好，
优先使用它的组合单图即可。当前缺少这两项前提的直接证据，因此只批准小规模筛选，不进入完整模型改造。

当前方案是有明确接口、预算和否决条件的研究方案；它还不是一个已验证的性能优化算法。
本阶段交付不包含新的加速百分比，也不宣称已经成立毕业设计的原创性。

后续[机制审查](aclgraph_multigraph_mechanism_screen_zh.md)复算了原始 128 步的实际目录，
容量削减空间为 1.192%；同时确认当前 GDN 已用混合核，不能沿用旧 Vector 阶段的互补预算。
它还收紧了“有限图预算”的论据，并将跨设备 PP 列为需先核算形状与填充成本的后备分析，
尚未新增已通过净收益门槛的方案。

进一步的[PP2 离线账本](aclgraph_pp2_offline_screen_zh.md)已补齐分组、矩阵形状、
逐层权重与 compact 状态内存、闭合单步流水条件和接口缺口。
它没有通过深入实施门槛；历史 68 张完整图的阶段资源记录还限制了“组合图库必然放不下”的论据。
后续仍需先找到强基线下的有用执行选择，再证明动态组合或独立图的额外贡献。

## 2. 为什么图数量本身不是算力来源

给定同一批输入、相同 kernel、缓冲区、流和依赖，如果某次多图回放的执行序列固定，
通常可以把这次序列表示成一个更大的 DAG。只要运行时支持捕获这些跨流依赖，
组合单图也能表达同样的并发关系，并减少外部 replay 调用。
这是执行结构的分析，不保证不同 graph handle 在底层一定得到完全相同的排程或实测时间。

所以，固定两路流水即使有效，其计算收益也来自解除了整批依赖；
还需进一步解释为什么要使用多张独立图。

多图比较明确的能力边界是：每步可以选择不同的已捕获模块、大小和模块间顺序，
而不必为每种完整组合都捕获一张大图。要把这种能力转化为性能，必须同时满足：

1. 动态状态使最佳组合发生变化；一个固定的组合单图不足以覆盖。
2. 独立模块复用确实比缓存全部有用的组合更省实际图资源。
3. 选图、数据整理、额外 replay 和 join 的成本小于适应性带来的节省。
4. 相比同等资源预算下的 Padding 仍有完整 step 净收益。

这个优势以固定拓扑、当前图更新能力和有限捕获预算为条件。
若单图已经通过动态描述符、内部工作队列或条件节点实现同样选择，应把它纳入基线。
本机条件图此前返回不支持；这只说明当前运行栈限制，不证明多图拥有普遍不可替代性。

### 默认容量重新穷举

从最近实际运行报告读取默认 capture list，对 B64～B128、每请求 Q4 的 65 个 batch 全枚举。
允许两个完整请求容量相加、不超过对应 Padding 容量时：

- Padding 总容量为 25,344 token；最小合法双图容量合计 25,024 token，只少 **1.263%**。
- B98 的整图容量是 400，可拼为 200+192；不是新增 49 请求容量。
- B127 的有效 508 token 没有精确双图组合，仍至少需要 512。
- 最近融合探针还要求两 lane 满足 TP2/Q4 对齐且总容量属于默认目录；在这个更严格契约下，上述范围的容量削减为 **0%**。

这只是计算容量计数，不是时延上界：kernel 形状跳变可能产生非线性性能差异。
但它否决了“默认表下简单拼图就能少算很多”的解释。

同一穷举中，有 1,071 个有序合法容量对、涉及 48 个 lane 容量。
这说明全部组合缓存与模块复用的数量可能不同，但其中很多组合会被支配，根本不值得捕获。
不能把 1,071 当成必须捕获的组合数，也不能把 2×48 张模块图与其直接比较就宣称节省显存。
真实预算还包括每图任务数、流、scratch、状态暂存和实际 allocator 驻留字节。

## 5. 候选取舍

| 候选 | 多图增加的自由度 | 当前证据与判断 | 优先级 |
| --- | --- | --- | --- |
| 动态组合独立模块，按状态选择分组、顺序和有限领先范围 | 使用同一模块目录组合不同执行图，不为每个完整组合捕获大图 | 有运行时动机；尚无“不同状态的胜出方案改变且净胜 Padding”的证据 | 主线候选，先过离线/小 profile 门槛 |
| 两张相同完整 decoder 图持续并行 | 两个请求链可独立推进 | 真正多图历史结果退化明显；重复权重读取、小 GEMM、update 翻倍均未消除 | 淘汰当前直接扩大方案 |
| 两张不同 attention 专用图并行，共享整批 dense | 可独立选择 kernel/资源配置，不拆大投影 | 旧 KV 分组和核额并发已有负证据；需先证明专用路径有稳定净收益 | 仅作为主线模块候选，不能直接重做旧排序实验 |
| 跨生成 step 的独立请求滚动执行 | 已完成请求不等待其他请求再进入下一 step | 需要真实 sampling/接受结果和调度语义，改变端点，且小 batch 效率风险未消除 | 后备研究，不用于完成当前单次 replay 目标 |
| 公共 Down/RS、局部 Norm、AG/MM | 保留大矩阵并改变通信放置 | 接口存在；属于公共通算融合，可继续资格核查 | 辅助路线，收益同时给 Padding |

主线的潜在贡献是**捕获预算、请求状态归属、动态执行选择与通信顺序的联合设计**，
不是单独的成本表或路由开关。当前已有 `planner.py`、独立 lane 和交错 update，
不能把这些现有组件重写后当成新贡献。

## 6. 主线候选的完整执行结构

### 6.1 模块边界与每步流程

首次只选择一个真实 FIA 闭合段；先把 TP collective 保留在公共整批段，
避免让两个未验证的图在同一 HCCL 通信域内竞争提交。
模块目录沿用默认容量，权重共享，独立图仅持有自己的可写输入、输出、workspace 与 update 资源。

```text
本步真实请求/长度/页表
  -> 生成并确认执行计划
  -> 整批输入 Norm/QKV/RoPE、KV 写入（公共大图）
  -> 按本步描述符整理两组完整请求（成本计入）
  -> [独立 attention 图 A || 独立 attention 图 B]
  -> 所有有效输出恢复到原请求行序
  -> 整批 O/归约、Norm、GateUp、Down/归约（公共大图）
  -> 完整 hidden/residual 与本步状态端点
```

这是最小的多图接口审查结构，不承诺 FIA/FIA 并发能够获益。
历史 whole FIA 已胜过简单两分支，所以若没有新的专用 kernel 或资源互补证据，
不实际重跑这个旧结构；此时直接否决该模块候选。

后续只有在明确的临界路径预算支持时，才允许请求组跨到 O/通信边界之外。
公共大 GEMM 在何处重新合批，需要与领先范围一并选择，不能默认全模型一直拆开。

每步计划包含 `step_id`、请求身份摘要、父容量、lane 容量和实际请求数、
行映射、模块签名、执行次序、合批点与 collective 序列摘要。
只用回放前已经存在的 host 信息作决策；不提前使用未知 token 或接受结果。
同一物理模板固定地址，不假定运行时能任意改写捕获指针。
不同容量对应不同模板；无法直接 view 的重排必须通过固定缓冲和显式拷贝闭合。

### 6.2 选择规则

候选集合必须包含整批 Padding。代价按完整端点估计，覆盖选择、H2D、update、
图提交、整理、干扰与最终等待。只对已资格验证的组合预测，未知组合选择 Padding。
不能仅按 KV token 总量线性外推，也不能把多个并行阶段时长相加作为回放时间。

路由应输出可解释的决策：所选组合预计比 Padding 省在哪里、要支付哪些额外成本。
只有净收益的保守估计高于测量波动与额外运行时成本，才选择多图。
启用阈值由先导噪声和实测成本决定；不先编造某个必然达到的加速率。
一个依靠始终回退 Padding 获得“零退化”的策略，不能声称多图目标已完成。

### 6.3 缓冲与状态生命周期

| 对象 | 所有权与完成条件 |
| --- | --- |
| 模型权重 | 共享只读；不增加 attention 或 MLP 权重副本 |
| lane 输入/输出/workspace | 绑定独立模板和使用代次；直到执行与输出恢复全部完成后才能复用 |
| host 长度和参数对象 | 一次 graph update 的绑定对象持续存活到 update 与 replay 完成，不能提前改写供下一步使用 |
| KV 历史页 | 可只读共享；本步可写 slot 必须按请求身份不重叠，当前 K/V 写入完成后才能 attention |
| hidden/residual | 两者均在正确映射与最终归约后交付；不能只恢复 hidden、遗漏 residual |
| GDN 状态 | 首个模块资格阶段不并发重入现有互斥 backend；后续如扩展，需独立事务和 workspace，commit 完成后才能再读/复用 |
| 完成事件 | 分别覆盖输入准备、真实 update、执行、结果归位与状态 commit；最终端点包括全部必要事件 |

同一请求的下一步仍等待本步 token 决定与状态完成；不同请求的独立性不解除这一依赖。
拒绝不合法计划必须发生在提交前。若已经有图在等待 ExternalEvent，提交失败时不能局部重试 Padding。

### 6.4 TP 通信顺序

当前 `DistributedPlanCoordinator.agree` 明确拒绝 `execution != "serial"`。
不能只把这个条件删掉，便称为支持多卡图并行。

最小 attention-only 独立图不包含 HCCL；公共图上的 collective 保持原始顺序，所有 rank 一致。
后续若确实要在独立图间掩盖 TP 通信，须增加显式通信序号，例如
`(step, segment, lane, boundary, operation, shape, dtype)`。
所有 rank 在提交任何模型 collective 前确认相同计划；每个 ready 生产者依序把通信交给同一序列，
不能按本地就绪先后自行挑选另一路 collective。

通信等待只针对所需生产者，不能无条件同步两路；但固定通信顺序形成的队首等待必须计入成本。
现有 A2 融合说明要求同一模型使用相同融合通信域；不假定可以复制多个域消除排队。
如需切出独立通信图或使用外部事件，先验证本机手工 ACLGraph 的实际支持，不能把 API 声明当成通过。

## 7. 成本预算与明确的否决条件

设相同分段版本串行完整端点为 `T_serial`，并行完整端点为 `T_parallel`，
同轮公共能力一致的 Padding 为 `T_padding`：

```text
切分额外成本 F = T_serial - T_padding
并行净节省   S = T_serial - T_parallel
超过 Padding 的必要且充分的实测条件：S > F
```

这是同输入、同完整端点的实测恒等式；不把它当成事前准确预测。
对于独立图与组合单图，还需要独立图因动态选择获得的节省，
大于额外 replay、跨图事件、固定地址整理和资源占用成本。

已知约束：融合两层中 `F` 为 167～199 μs，`S` 为 81～106 μs，仍差约 86～93 μs。
这些数字否决当前两次小融合结构，不能直接作为新的专用 kernel 预算。
约 3.74～3.78 ms 的同轮融合 Padding 若希望改善 5%，需净省约 187～189 μs；
这个量级高于当前全部净缺口的简单回收，不能只凭消除一次微小启动就预测达到目标。

历史完整模型的 Down 前后可见调度空隙合计约 0.08 ms，
因此 SET 类“消除 kernel gap”在这些已观察边界上缺乏多毫秒预算。
尚未覆盖的间隙需要单独量化，不将已被通信或状态工作覆盖的时间重复计算。

停止规则：

- 多图专用版本在任何代表性状态都未胜过同等优化 Padding：停止该候选，不建立路由器。
- 两种动态状态始终同一固定方案胜出：不宣称动态组合优势，优先其组合单图。
- 两状态虽有排名翻转，但幅度不足以支付选图与跨图成本：停止动态调度候选。
- 图资源实际测量不优于组合单图目录：不再使用“组合爆炸”作为必要性论据。
- 并行只让算子重叠增加，完整端点不减少：没有完成性能目标。
- 当前资格条件不足：只报告缺口，不扩大到长轨迹或全模型。

## 8. 最小验证顺序

### P0：已有证据与适应性门槛，优先完成

本轮已经完成源码分类、五份远端报告取回、匹配历史完整源码和容量穷举。
最新完整模型组合单图的两个动态 step 确实有微小的排名变化：B98 的设备中位数切分快 0.276%，
B73 慢 0.094%。对两个 step 的中位数事后分别取 Padding/切分较小者，
相对最佳固定策略只再增加约 0.045 个百分点的设备改善；墙钟几乎没有额外空间。
这只是两项中位数的事后聚合，不是在线路由结果，不替代原五轮配对均值，
也不是其他调度的收益上界。它提示“只在这两个旧策略之间加路由”不足以成为大收益主线。
这些图仍是组合单图，不能把该微小排名变化当成独立多图的净收益证据。

下一项只补一个问题：是否存在至少两个有代表性的动态状态，适合不同的合法执行方案。
优先从原动态轨迹选状态，按事先规定的 batch/KV 工作量分层选取，不按测出的收益选样。
如果历史样本没有所需状态，先做两个状态的窄 profiling；不扩模型、上下文或卡数寻找极端案例。

没有观察到新资源窗口或专用路径改善，则 P0 失败，本主线候选暂不实现。
目前 P0 的适应性前提仍未证明，不能把后续内容写成已通过的路线。

### P1：一个闭合段、四个主对照

P0 通过后才实现：

1. 同等公共融合能力的整批 Padding。
2. 两张独立子图串行。
3. 同两张独立子图并行。
4. 相同 kernel、分段和流依赖的组合单图。

先每个动态状态至少三轮，轮间反转模式次序；每轮样本数由先导波动决定，
不以少量正样本提前停止，也不为无关条件追加完整测试矩阵。
性能使用无 profiler 计时；只对需要解释的端点另采一次 trace。
主指标是逐样本慢 rank 的完整 wall/device 时间，两者同时报告；原始 rank 样本保留。
相同算法 eager/replay 的输出、完整状态与 inactive/null 行严格检查；
跨算法量化数值差异，不能把微小 BF16 漂移直接当状态破坏，也不能只检查 finite。

明确记录本次 replay 调用了几个独立 graph 对象、输入地址、task 数、图资源和最终 join。
所有真实 FIA update、host 选图、数据拷贝、状态提交都在完整端点范围内。

### P2：动态组合的同预算验证

只有 P1 出现至少一个净胜状态且不同状态的最优组合不同，才进行原轨迹验证。
使用同一固定默认目录，比较静态最优方案、预算内组合单图库、动态独立图库与 Padding。
候选数先从两种调度开始，不捕获全部 1,071 个理论容量对。
固定轨迹和规则后测试，训练/标定与测试样本分离，不能在计时结果上事后选赢家。

预算同时约束实际图驻留字节、峰值 scratch、流资源和捕获时间。
报告动态轨迹均值、P50/P95/P99、退化状态、选图开销与资源消耗。
若只减少捕获时间而稳态不改善，应按缓存工程结果报告，不称为推理并行收益。
后续完整模型接入必须等本阶段报告，再扩大到少量边界。

## 9. 与已有工作的可写贡献边界

现在能够确认的工作包括：本机默认容量和图更新契约、真实多图/组合单图的证据分类、
公共融合强化后碎片化成本的量化、跨 rank 并行计划的实现缺口，以及明确的候选否决协议。
这些是分析和实验贡献，不是已经得到的新加速方法。

如果主线后续成立，论文需要证明联合决策比固定 DBO/静态图缓存/已有成本表多解决了什么，
并用“去动态选择”“去并行”“改组合单图”“相同预算”等消融分别支撑。
不能把硬件换成 A2、改中文名称或调用已有融合接口作为算法新颖性。
