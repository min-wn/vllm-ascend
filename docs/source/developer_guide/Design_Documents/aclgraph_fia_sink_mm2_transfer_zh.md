# 注意力搬运分块与计算分块解耦：实验与负结果

日期：2026-10-19。

## 用简单的话说明进度

最初希望把一个动态批次分给多张已有图并行运行，减少填充浪费。
目前保留了这套探索，但已有结果还没有证明切分并行优于默认填充。

后续主线转向图内注意力调度：固定图的容量不变，每步把真实请求长度和页表交给
设备端计划生成器，再分配每个核负责的请求和注意力头。完整请求/注意力头归属策略
在完整动态描述符轨迹中观察到约 1.79% 的平均改善，但其中一轮变慢，P99 也退化。
它仍是合成注意力链结果，尚无完整模型或在线服务收益结论。

最近尝试把运行中的输出累加值留在片上。正确性检查通过，反向顺序复测却未保持收益，
因此先保留为隔离候选。本轮转向另一个有明确源码依据的目标：减少小块搬运和同步。

## 与图切分的关系

“多张图并行”与“一个算子内部的工作分配”是两个层次，不能混用名称。
本轮修改位于官方注意力算子内部，填充与多图切分都可以使用，**不需要图切分才能成立**。
它可以提供更好的共同算子基线，不能作为切分必要性或切分独有收益的证据。

毕设允许保留两类结果：一类证明切分创造了其他方案无法使用的执行机会；
另一类是在动态形状 ACLGraph 上有足够价值的独立优化。
任何后续切分/填充对照，都应让双方获得同样合法的算子优化。

## 发现的具体问题

D256 的一次矩阵计算需要更宽的数据。此前的安全适配把第二次矩阵乘法（MM2）
的 K 分块限制为 64 行，保证 L0B 的半区容量不越界。
原实现也把 GM 到 L1 的搬运批次绑定为同样的 64 行。

但 L1 与 L0 是不同层的片上存储，它们不一定需要采用同样的分块尺寸。
当前 V 区有两个各 32 KiB 的槽位；可以尝试合并为一个 64 KiB 槽位，
一次搬入 128 行，再分两次安全的 64 行计算。

```text
原实现：搬 64 行 → 算 64 行 → 搬 64 行 → 算 64 行
候选版：搬 128 行 → 算前 64 行 → 算后 64 行
```

总 V 存储仍为 64 KiB，整个 L1 静态分配仍为 464 KiB。
L0A、L0B、L0C 的容量和 64 行计算上限不变。
MM1、真实长度、页路由、计划、softmax、工作区递推和图容量均保持原样。
减少的是搬运调用、部分页表解析和相应的事件组；必要数据字节数与计算量并未减少。

这也有代价：原来的两个 V 槽位变成一个，可能降低搬运与计算重叠的机会。
因此源码工作量下降不保证延迟下降，必须用实际设备对照判断。

## 实现和验证范围

补丁仅接受固定版本、已完成 D256 安全适配的 Cube 源码哈希，拒绝版本漂移和重复打补丁。
通过独立编译宏 `THESIS_FIA_MM2_WIDE_V` 做同源开关对照，
不叠加此前的 running-O 驻留修改。

本轮只编译原有两个受限分块键 `104000000010222223` 和 `104000000010322223`。
目标为 A2、BF16/TND、Q4、Q12/KV2、D256、分页 ND128、无额外 sink/RoPE。
没有安装或覆盖系统算子包，原有构建与基线保持独立。

设备实验按基线→候选→候选→基线的顺序启动四个独立进程。
每个进程固定种子 1703、16 份私有合成 Q/K/V、5 次预热、
每容量 10 次常规计时，并另做一次性能剖析。
全部 80 次计时保留，两个相反顺序的配对分别报告。

完整计时包含准备、必要 H2D、真实计划生成、图回放和最终等待。
计时前后保留全部输出哈希、1024 字计划、FP32 抽样、精确零填充和地址/描述符检查。
性能剖析与常规计时分开。

本地 73 项定向检查通过；原生 C++ 使用实际 Axis 实现验证了
1026 个长度、尾块、容量和计算顺序对照。
这些检查不替代设备同步正确性或性能验证。
两个受限版本均已完成设备编译与本轮运行。

资格验证与证据检查结果：

- 80 次常规计时保留，计时与剖析分开。
- 144 行 FP32 抽样全部通过，最大绝对误差为 0.00029981881380081177。
- 两个容量下，四个进程的 16 份完整 BF16 输出哈希均相同，且前后未变。
- 24 次完整计划核对通过，包括 8 次捕获前元数据检查和 16 次计时前后检查。
- 原始文件、受限分块键、准备复制、私有输入和实际任务轨迹均通过审计。
  另一份脚本直接从原始计时重算均值和中位数，结果一致。

这证明本轮没有观察到数值变化，不构成所有形状正确性的证明。
它否定了“减少搬运批次就能改善该路径延迟”的简单判断。
由于搬运分组与 V 槽位数同时变化，尚不能把退化全部归因于双缓冲丢失，
也不能只根据源码调用数判断重叠程度；必须单独消融。

## 与已有工作的边界和下一步

不同存储层使用不同分块尺寸，以及批量搬运，都是已有的算子设计方法。
本轮贡献候选是定位并修正当前受限 D256 适配中的具体绑定关系，不能预先宣称新算法。

本轮不满足推广条件。单 V 缓冲补丁保留为可复核的负结果，不接入正式模型路径。
它不能计入此前约 1.79% 的动态注意力链收益，也没有新增完整推理或切分收益。

后续候选仍优先要求能说明切分创造的并行机会；若独立算子优化具有更大收益，
也可以单独成立。两者在论文和实验中分别归因。

针对本轮负结果，下一项最小核查是**在保持两个 V 槽位的前提下重新分配 L1**。
D256、无 RoPE 时，MM1 的最大 Q 子块为 128 行，按 256 列 BF16 计算为 64 KiB，
小于当前每槽 96 KiB。若两槽 Q 都安全缩到 64 KiB，恰好能腾出 64 KiB，
把 V 从两个 32 KiB 槽扩大为两个 64 KiB 槽，总量仍为 464 KiB。
这是容量算术上的可行性；还没有修改 Q/V 分配、几何分派或事件实现，
不能视为该候选已经安全，更不能视为已获收益。

实施前必须核对 Q 搬运的对齐/步长、Load3D 地址、跨任务快照和全部在途生命周期，
并在进入缩小布局前拒绝或分派不合格几何；不能仅在内部关闭 128 行搬运后，
仍让不合格输入使用缩小的 Q 槽。随后以同一双缓冲布局对照 64/128 行搬运，
才能区分分组收益与缓冲布局代价。如果门槛不通过，就停止，不继续堆叠修改。
