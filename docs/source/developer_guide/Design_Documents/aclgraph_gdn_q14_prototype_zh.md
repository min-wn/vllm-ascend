# Q1/Q4 共用 compact 状态的单层原型

本轮保留原 Q4 ready 基线、约 2.67% 离线真实生成循环收益，以及全部跨算法数值与任务质量失败记录。
新原型只检查 Q1/Q4 是否能连续使用同一份 compact FP32 base/log，并判断其单层成本是否有竞争力。
不接 runner、不排查 stream 故障、不做 dense/compact 双状态桥接，也不扩展 Q2/Q3。

## 冻结契约

- 当前 query 长度用 `sequence` 表达，取 1 或 4；上一轮接受长度单独用 `accepted` 表达。
- packed 输入首行的 `ids[begin]` 决定 owner，不使用 `ids[begin + accepted - 1]`。
- 每个 owner 只有一份 FP32 base 和最多四条小日志。发布宽度写入八个 int32 validity lane。
- 提交只消费上一轮合法接受前缀；新查询的长度不限制上一轮的接受长度。
- Q1 不产生三个 filler 候选。日志的无效尾部清零，诊断导出的尾部重复最后合法态，但不算有效候选。
- Q1/Q4 切换不经过 dense 导出、复制和重新导入。最终物化仅在实验生命周期结束时发生。
- FP32 精度、逐 token 解算次序、64+64 规约树和 20 AIC / 40 AIV 核资源保持原样。

独立源码位于 `benchmarks/multi_graph_gdn_q14_kernel/`，模块名 `gdn_q14`；旧内核目录不改。
Q1 的 Cube 仍使用固定八列容量，只有第 0/4 列有用，不能声称 Cube 乘法量缩为四分之一。
消费侧只执行当前有效 token 的递推，但部分固定容量清零、规约、产品与日志搬运仍保留。

## 数据来源及边界

按时间扫描旧短文本生成 ledger，选择第一个覆盖全部四种 owner 切换、且含 mixed step 的连续 16 步窗口。
结果为第 54～69 步、56 owners、896 次请求验证，包含 Q1 812 次、Q4 84 次。
四种切换的次数依次为 700、70、56、14；10 步全 Q1，6 步 mixed。
实际 query 行数为 1,148，旧强制 Q4 为 3,584，其中 2,436 行为 filler。行数变化不是时延收益。

原 ledger 没有持久化这一段的连续层激活。本轮复用已有 Qwen3.5-27B TP2 的 rank0、layer4 真实 recurrence site。
按冻结映射为 ledger owner 选择 source owner，重复使用其四行真实输入；Q1 仅取第一行。
各实现从同一合法接受态独立连续推进。
报告必须保留 `input_mode=real_site_reuse` 和 `initial_state_matches_original_ledger_step=False`。
因此这是单层真实输入原型，不是原整网连续激活的精确复现，也不是完整 GDN 层或服务吞吐测量。
共同边界从已完成 Q/K L2 norm 的 recurrence 输入开始，不包含卷积、投影、norm、TP 和 LM head。

## 验证与对照

先验证接受前缀 1～4、四种切换、混合、重排、暂停恢复、输出、有效日志、接受态和终末物化。
新 delayed/ready 必须逐位一致；同源强制 Q4 只比较有效前缀及相同接受态，不把 Q1 的无效尾部当作候选。
CPU 标量协议 oracle 只证明生命周期与代数契约，不证明设备舍入或模型质量。

原生对照保持自己的 dense 连续轨迹。进入当前 Q1 前先选出上一轮真正接受的 dense 槽；不能把接受 2～4
直接当作当前 Q1 的索引。纯 Q1 用原生 recurrence；mixed 用 Q4 recurrence 加 Q1 chunk。
在本机核实 FLA capability 与实际 callable 后，直接使用已安装 chunk 算子，保留其 gather、转置、scatter 和输出归位。
共同输入已经 norm，chunk 禁止重复 norm；这不是完整原生 runner 接入资格证明。

计时包含必要元数据准备与上传、fixture 激活 gather、固定容量 Q/K 转换、recurrence、状态提交和最终等待。
初始化与终末物化单列，并计入生命周期合计；初始化每个样本实测，不重复引用一次冷启动结果。
图捕获和资源分配单列。固定图容量沿用所选 ledger 已有容量，不搜索 bucket。
三轮交替执行顺序，每轮保留重复样本。只做这一组混合片段，并取首个 mixed step 的 Q4 owners 做一个 Q4 成本控制。

稳定判据在查看设备结果前冻结：三轮均正收益、合并收益大于 1%，且大于两倍较大的轮间相对跨度。
若混合链不满足竞争力要求，保留证据并结束扩展，不继续枚举布局或桥接。

## 设备验证结果与收口

**结论：Q1/Q4 共用 compact 状态在本轮正确性检查中成立，但没有取得相对冻结 Q4 ready 的完整生命周期增量收益。本轮原型扩展结束，不进入完整层或 runner 集成。**

原 Q4 ready 的全部成果、约 2.67% 离线真实生成循环收益及既有质量失败记录继续保留。
没有开展 AIME、FP16、FP32 head 或跨算法整网质量复验，也没有新增路由器或其他内核候选。

### 正确性

- CPU 协议测试 66 项通过，覆盖宽度、接受前缀、owner、重排、暂停恢复与冻结轨迹完整性。
- Ascend910B3、CANN 9.1，torch 2.10.0+cpu / torch_npu 2.10.0.post4；卡 0 单层 rank0 site。
- 独立模块 build-v2 编译成功。首次编译的动态 DMA 类型窄化失败完整保留，未改原 Q4 源码。
- 小型真实输入用例覆盖上一轮 Q4 接受 1、2、3、4 后进入 Q1/Q4，以及 Q1 的两种后继、混合、重排、暂停恢复。
- eager 与 ACLGraph 两种方式均通过：新 delayed/ready 的输出、完整日志、发布宽度、接受 base 和诊断候选逐位一致。
- 与冻结强制 Q4 相比，有效输出前缀、有效日志、接受 base 和有效候选逐位一致，终末物化逐位一致，终末日志和 validity 清零。
- 第 54～69 步的完整 16 步图回放审计也通过上述 compact 检查；该真实 ledger 的接受长度均为 1，不冒充接受 2～4 的真实轨迹。
- 原生对照维持自己的 dense 轨迹；逐步输出及终末态均有限。相对 compact 的最大输出 NRMSE 为 0.177622%，终末态 NRMSE 为 0.085332%。这是局部差异记录，不是整网质量资格。

从旧 site 构造共同合法初态、一次性上传 source 激活属于公共 fixture 搭建，位于计时外；这不是从模型 prefill 开始的完整请求生命周期。

### Q1、Q4 与混合成本

以下为 NPU event 分段区间的每 step 均值，单位 ms，覆盖全部重复样本。
前两类来自同一连续片段：Q1-only 为 56 请求、10 步；mixed 为 56 请求，其中 Q1 42、Q4 14，共 6 步。
Q4 独立控制仅取第一个 mixed step 的 14 个 Q4 owner，一步；它的 batch 不同，不能与前两行当成纯 query 长度消融。
三侧使用相同请求、有效输入、接受前缀和状态初态，最大容量仍沿用 ledger 的 56 请求 / 224 行。

| 负载 | 强制 Q4：含准备 step / 图区间 | 新 Q1/Q4：含准备 step / 图区间 | 原生控制：含准备 step / 图区间 |
| --- | ---: | ---: | ---: |
| Q1-only，56 请求 | 1.035307 / 0.314736 | 1.105301 / 0.236248 | 1.440452 / 0.347243 |
| mixed，42 Q1 + 14 Q4 | 1.045075 / 0.323097 | 1.124267 / 0.262387 | 4.681952 / 3.488784 |
| Q4 独立控制，14 请求 | 1.076170 / 0.126599 | 1.023664 / 0.125763 | 1.456980 / 0.288243 |

“图区间”包括 Q/K 转换、图启动、solve 和 commit，不是 kernel-only profile。
“准备区间”同时包含 CPU 元数据生成、必要上传、fixture 的真实输入 gather 和调度空隙，不能全部称为 CPU 开销或同步开销。
图内区间在 Q1-only 与 mixed 上都缩短，但本 probe 的准备区间总均值由约 11.538 ms 增至 13.862 ms，抵消了图区间约 1.149 ms 的节省。
本轮没有定位准备区间增加的具体来源，不能把它全部归因于 Q1 recurrence，也不能假定接入 runner 后会消失。

### 实际计算与搬运

Q1 每请求只递推一个当前 token，无三个 filler。但以下固定容量代价仍存在：

- Cube 每请求仍是八个 M384/N8/K128 乘积，共 3,145,728 MAC；只有第 0/4 列有效。
- 每 value head 仍读 1,024 个 FP32 product、读/写 1,056 个 FP32 日志；旧接受态提交还须处理完整 128×128 base。
- Gram scratch 清零 8,192 个 FP32 元素，并保留 64 组长度 64 的规约，以保持原规约顺序。
- Q1 当前输入 payload 每 value head 为 912 B，Q4 为 3,648 B；当前输出分别写 256 / 1,024 B。
- gate/beta 的跨 value-head 重复加载仍保留；每请求 gate Exp 数为 Q1 576 / Q4 2,304，未冒充已经解决重复计算。
- 两种 compact 图都执行固定最大容量 Q/K 转换。Q1 只减少有效消费，不代表所有算术和搬运都减为四分之一。

这些是源码逻辑请求数和 payload，不是实测 HBM 字节、周期或瓶颈占比。

### 去留与限制

本轮证明了“当前 query 长度”和“上一接受长度”可以解耦，Q1/Q4 可以原位共用 compact base/log，且不需要模式切换时的 dense 桥接。
但对目前完整测量链，新原型没有超过已冻结 Q4 ready；按事先约定结束本轮扩展，不进入完整层或 runner，不继续枚举新布局。
失败结论针对这份原型和复用真实输入的测量边界，不是“变长 compact 在任何实现下都不可能有收益”的结论。
原跨算法数值、真实文本初筛与 AIME 失败记录保持有效；本轮无权用局部逐位一致或更快控制覆盖它们。
