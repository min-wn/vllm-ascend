# 输入投影切分、GDN core 前合批：小实验结果

日期：2026-10-19。

## 1. 结论

**本次三轮小实验中，新方案超过了同轮 Padding，设备耗时减少 2.17%～2.43%，
墙钟耗时减少 1.85%～2.22%。** 合批复制、状态提交、所有段内归约和最终流汇合均已计时。
这是使用真实权重和状态的局部闭合计算段，不是全模型或服务端加速。

这个结果支持上一轮 profile 给出的判断：不必把整条下一层计算都切开。
只拆能利用前层通信窗口的输入投影，在 GDN core 前恢复整批执行，
可以在当前条件下让提前执行的收益超过额外切分成本。
当前收益幅度仍小，未证明在其他动态 batch、层边界、完整模型或更强融合基线上成立。

## 2. 这次实际修改了什么

此前路径在下一层 O 前合批，卷积、GDN core、gated Norm 和 commit 都执行两份。
本次改为：

```text
整批前层 Norm / GateUp / 激活
    → 两块 Down GEMM（均先于下一层 GEMM）
    → 有序提交 Down A / B 归约
    → A 归约完成：提前执行 A 输入 Norm / QKVZ / BA
    → B 归约完成：执行 B 输入 Norm / QKVZ / BA
    → 拼接投影结果与残差
    → 一次整批卷积 / GDN core / gated Norm / commit
    → 整批 O / 归约 / MLP / 归约
    → 等齐所有状态工作并输出
```

实现位于 benchmark 的 `--join-before core`，未改生产 runner 或 backend。
`join_projected_phases` 只接受同一个 adapter 的有序 left/right、尚未执行 core 的投影，
按请求行拼接 mixed-QKV、z、b、a、已初始化 core_output、residual 六个张量。
六次拼接都在图内计时；core 使用 full metadata 和 full backend，一次提交状态。
core_output 的清零与复制也保留，没有通过删除 inactive 输出初始化获得收益。

共同条件沿用上一轮：910B3 双卡、Qwen3.5-27B BF16、TP2、Q4、B98；
默认捕获容量 400 个词元，分支为合法的 200+200，即 50+48 个有效请求。
没有为 B98 增加专用容量，没有 attention-head 图切分或额外 attention 权重副本。
所有控制共享 NZ 权重和 ready-tile compact recurrence。

端点仍是第 3 层完整 MLP 到第 4 层完整 GDN（含其 MLP），
入口为合成的已归约 O 输出和 residual。前层 FIA/update、主机元数据构建、
完整模型和 draft model 不在范围内；没有省略本端点必需的状态处理。
每次独立计时恢复同一一致状态；动态状态连续性用三步资格检查单独验证。

## 3. 三个对照及结果

- Padding：前层与下一层都整批执行。
- 切分等待：采用新合批位置，但等 Down A/B 都归约完成才开始下一层投影。
- 切分提前：与切分等待完全相同的算术和合批方式，仅允许 A 投影提前。

每模式三轮，每轮六个有效样本；轮间交替模式执行顺序。
逐样本取双 rank 较慢耗时，再算轮内中位数。单位为微秒。

| 轮次 | Padding 设备时间 | 切分等待 | 切分提前 | 提前相对等待减少 | 提前相对 Padding 减少 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 1 | 2843.17 | 2935.10 | 2774.16 | 160.94 | 69.01（2.43%） |
| 2 | 2836.74 | 2930.66 | 2775.26 | 155.40 | 61.48（2.17%） |
| 3 | 2844.08 | 2937.57 | 2779.11 | 158.46 | 64.97（2.28%） |

墙钟 Padding 为 2972.76～2979.24，切分提前为 2913.04～2918.81；
逐轮减少 66.20、55.09、58.31 微秒，即 2.22%、1.85%、1.96%。

这里能作一个直接的端点账目：
**同轮切分等待比 Padding 多约 92～94 微秒；消费者提前执行收回约 155～161 微秒；
最终净减少约 61～69 微秒。** 这不是把不同 kernel 的耗时强行相加，而是三个端点的测量差。
切分等待本身已经允许前层 Down B 与 Down A 通信重叠，因此两条切分路径的差值
主要检验下一层消费者提前执行这一依赖变化。

上一轮 O 前合批的提前路径为 2921～2934 微秒，本轮约为 2774～2779 微秒，
与减少重复处理的方向一致；但两轮属于不同进程运行，不能将该差直接作为严格同轮消融。
本次超过 Padding 的结论取自本轮自己的 Padding 对照。
样本只支持小规模筛选，没有检验 P99、长期稳定性或统计显著性。

## 4. Profile 验证了什么

六份 trace 均与预期算子数量吻合：

| 路径 | MatMul | AllReduce | solve | commit | CausalConv1d |
| --- | ---: | ---: | ---: | ---: | ---: |
| Padding | 7 | 3 | 1 | 1 | 1 |
| 新切分路径 | 10 | 4 | 1 | 1 | 1 |

所有下一层 GEMM 均在前层 Down B GEMM 结束后开始，没有让两代 GEMM 争抢 Cube。
提前路径的 A 输入 GEMM 与最后一块归约重叠约 120.70～132.26 微秒，
包含前处理后主流覆盖该归约约 140.24～154.50 微秒。
等待控制的对应重叠为零。完整 core 在两块输入投影都结束后启动。

六次合批的总 kernel 时长为 38.78～38.84 微秒；
此外官方 core 内部原有的一次拼接仍保留，不能与这六次混淆。
新提前路径的主流非 GEMM/非 solve 工作约 293.77～302.36 微秒，
上一轮 O 前合批约为 427.36～436.89 微秒。
该工作量变化与删除重复卷积/布局处理/状态准备的目标一致；
不同运行的 profile 只作定性归因，不把这些差值当作精确可兑现的关键路径收益。

本次将跨 rank barrier 放到 profiler 初始化之后，减少了上一轮毫秒级偏差，
但首归约仍有约 0.27～0.86 毫秒的异常等待，部分输入 GEMM 的 profile 时长也有波动。
因此整体性能继续只采用 profiler 前的独立计时，
不使用 profile 总跨度或首个 collective 来估算硬件带宽和净收益。

## 5. 正确性检查和限制

两个 rank、三条路径均通过 B98→97→99、接受前缀 1→2→3 的连续三步检查：
同调度 eager/replay 输出与状态严格相等；切分等待和切分提前严格相等；
inactive/null 状态不变、dense 初始化源不写回，输出和状态均有限。
CPU 测试还检查合批请求顺序、六个字段的覆盖、清零输出的保留、重复消费和非法阶段拒绝。

与 Padding 的数值诊断与上一轮记录相同：hidden NRMSE 约 0.00413～0.00458，
最大绝对差 0.0625；residual 最大绝对差 0.5～1.0。
原阈值 `0.02 + 0.02 * abs(reference)` 下，residual 三步仍有 4、3、3 个失败元素。
没有放宽阈值。诊断相同不等于两次运行输出逐元素相同，也不等于模型质量已验证。
本实验没有观察到新增的调度状态错误，但不构成正式精度准入或全模型质量结论。

## 6. 现在值得做的下一步

本次证明了当前局部条件下“拆必要的部分、及时合批”可以比 Padding 更快。
它也给出必须保留的控制：不提前执行时，新路径仍更慢，
所以收益不能只归因于换了一个更快的公共 core。

接下来优先把这个有收益的边界放入一个更长、包含真实上游输出的相邻层闭合段，
使用相同 Padding 公共优化，测量收益是否被前后依赖和状态生命周期吞掉。
这是范围验证，不立即扩大成全模型或多容量大矩阵。
若局部收益在整合中消失，应先 profile 定位新增同步/布局成本。

若继续优化此端点，明确的剩余开销是约 39 微秒的合批复制和输入投影碎片化。
固定整批输出缓冲区的分块写入可作为后续接口改造候选，
但需要矩阵输出布局支持；用六次 `copy_` 替换六次 `cat` 不等于消除搬运。
即使理想地消除全部约 39 微秒拼接，相对约 2.8 毫秒端点也仅约 1.4%，
不能包装成大幅端到端提升的方向；且这一上限忽略了新增写入成本和其他干扰。

毕设上可以保留的具体问题仍是“由依赖窗口决定最小切分范围和汇合位置”。
微批流水、计算通信重叠、合批本身不声称首创；
当前观察针对请求分组依赖，不能证明必须使用多张图，同样调度可以在一张 ACLGraph 中表达。
还需动态选择算法、与已有工作的具体比对及更长路径证据，才能形成完整贡献。
