# 完整模型中的局部请求切分与提前投影

日期：2026-10-20。本文记录完整模型接入实验；最终结果以随文归档的原始报告为准。

## 问题和方案

前面的两层实验在 Qwen3.5-27B、TP2、Q4、B98 下观察到约 0.78%～1.72% 的设备耗时下降。
这个数值只属于两层片段，不能外推成完整模型收益。

本次在完整的 64 层 decoder 和最终 norm 中，仅修改第 3→4、19→20、35→36、51→52 层边界
（层号从 0 开始）。其他层仍调用原有 forward。

每个边界的执行过程是：

1. 前一层 FIA、O 投影、GateUp 与激活仍处理完整容量。
2. Down 投影按请求切成 A、B 两段，通信流按相同顺序进行两次 AllReduce。
3. A 的通信完成后，立即运行下一层 A 的输入 norm 和投影，同时让 B 的通信继续。
4. B 就绪后完成 B 的投影；合并投影结果，只运行一次完整的 GDN 状态核心。
5. 后续 O 投影和 MLP 恢复完整容量。所有状态提交和流依赖都保留。

切分的作用是让第一部分请求提前成为下一层的合法输入，从而暴露原来整体 AllReduce 屏障后的计算。
不是减少模型层数、跳过 attention update，也不是复制 attention 权重。

## 对照和容量约束

三个对照共用 `deferred_tile_ready` attention 核心：

| 对照 | 是否切分 | 是否允许 A 提前投影 | 回答的问题 |
| --- | --- | --- | --- |
| Padding | 否 | 否 | 完整容量基线 |
| split_barrier | 是 | 否 | 切分自身增加多少开销 |
| split_early | 是 | 是 | 通信与计算重叠能否补回这些开销 |

用同轮完整耗时表示，净收益等于：

`Padding − split_early = (split_barrier − split_early) − (split_barrier − Padding)`。

第一项表示提前启动的收益，第二项表示切分额外成本。只证明第一项为正还不够；
只有第一项超过第二项，才能在该次完整模型执行中超过 Padding。
profile 内各 kernel 的时间和不能直接代入这个等式，它们只用于解释成本来自哪里。

先使用既有固定随机轨迹的前两步 B98、B73，不改轨迹、请求身份、真实长度和接受前缀。
由已安装 vLLM 的默认 dispatcher 得到容量 400 和 304；Q4 每个请求对应 4 个 token。
切分为 200＋200、152＋152，四个子容量均须存在于默认 capture size 集合中。
这里没有专门为某个 batch 创建新的容量。

完整模型图仍是一个带跨流依赖的图；本实验验证的是图内局部请求流水，
不能描述成已经完成了生产环境的任意多图调度器。

## 完整模型接入新增的成本

原模型循环需要接收一个完整的中间张量。因此前一层的两段通信输出会各拷贝到完整张量的对应区间。
紧邻的下一层只在对应事件完成后读取该区间；禁用辅助 hidden-state 输出与 sequence parallel。
该异步中间结果的契约仅限此受控实验，不是可直接开放给任意模型 hook 的通用接口。

初版合并 6 组数据：QKV、z、b、a、初始化后的 core output 和 residual。
这些合并、两次通信输出拷贝以及事件等待全部留在计时图内。

改进版的明确优化目标是减少合并成本：先合并 QKVZ、BA、residual 三组投影数据，
然后统一执行布局整理，并只初始化一次完整 core output。
它保持请求顺序、权重、状态核心和通信顺序不变。
CPU 测试检查普通布局和交错布局的字段一致性；硬件收益仍需同轮 Padding 对照确认。

## 验证口径

- 真实模型完成全部 128 个请求的 prefix；不是用随机状态代替完整模型 prefill。
- 每次调用都检查 64 层各访问一次，最终 norm 输出来自真实 model.forward。
- 每张图必须包含 16 个真实 FIA update task，保留 host 长度更新、metadata H2D 和最终流汇合。
- 连续两步分别进行同调度 eager/replay 输出和全状态精确核对，检查 inactive/null 状态。
- split_barrier 与 split_early 的最终输出要求精确一致。
- 跨 Padding 数值差异单列报告。相同调度重放精确一致，不等于跨 shape 模型质量已经认证。
- 无 profiler 的计时按每个样本取两张卡中较慢的一张，再做统计。
- profiler 只用于解释 kernel 数量、合并成本和通信重叠，不能将 profile 总跨度作为性能结果。

计时范围包含准备、真实 update、完整 decoder replay 和状态生命周期操作；
不包含 logits、采样、draft model、网络请求和服务调度，因此不是 serving 端到端结果。
仅两步轨迹和少量轮次属于收益筛查，不足以证明长轨迹或尾延迟稳定改善。

## 与已有工作的区别

微批流水和计算通信重叠本身不是新的概念；公共 ready-tile kernel 也同时提供给 Padding。
本方案需要独立验证的内容，是在默认动态图容量约束下选择局部请求切分边界，
在足以掩盖尾段通信后及时合并，以避免把后续状态核心和大矩阵都拆小。

毕设能讨论的机制是“有限范围的提前消费与合并边界选择”，而不是宣称提出了通信重叠本身。
只有完整模型对照证明重叠收益大于切分、拷贝和小矩阵损失，才能支持有效性结论。

## 初版完整模型结果

`full-core-join-v1` 已完成 3 个模式、2 个动态 step、5 轮无 profiler 计时。
全部模式的连续两步 eager/replay 输出和全状态精确核对通过。

| B / 默认容量 | Padding 设备中位数 | 提前切分设备中位数 | 提前切分相对 Padding |
| --- | --- | --- | --- |
| 98 / 400 | 122.334 ms | 122.402 ms | 慢 0.056% |
| 73 / 304 | 112.811 ms | 113.266 ms | 慢 0.404% |

全部十个样本的墙钟均值：Padding 126.855 ms、等待切分 127.801 ms、提前切分 127.175 ms。
提前启动平均省 0.626 ms，但切分新增成本为 0.946 ms，净结果仍慢 0.320 ms（0.252%）。
五轮设备时间改善率分别为 +0.070%、−0.170%、−0.536%、−0.264%、−0.950%；
仅第一轮为正，不能宣称稳定收益。

完整图 inventory 为 Padding 304 次矩阵乘、129 次 AllReduce；切分 316 次矩阵乘、133 次 AllReduce。
两者均保留 48 次 GDN solve、48 次 commit、16 次 FIA。
profile 观察到每个目标边界约 113～119 μs 的输入 GEMM 与最后一段 AllReduce 重叠。
但完整容量输入投影约 193～197 μs，切分后约 297～305 μs，合并张量还增加额外工作。
因此失败的原因不能简单归为“并行没有发生”。

同时发现，初版完整模型走普通 Matmul 路径，未像此前局部实验一样显式统一 NZ 权重。
故中间版本 `full-core-join-v2` 在 prefix 初始化阶段停止，未产生性能结果。
后续 `full-core-join-v3` 同时给 Padding 和切分启用全部 304 个 decoder 投影的 NZ 格式，
再使用三组 packed projection 合并。NZ 是双方共享优化，不能归为切分贡献。
这一后续实验改变了格式和合并两项条件，不单独声称两项各自的净收益。

跨 Padding 数值差异也不能省略：初版最终 hidden 的 NRMSE 为 0.873%～0.886%，
最大绝对差 0.4375～0.5；原逐元素阈值 `0.02 + 0.02 * abs(reference)` 有 13671～18518 个元素超出。
residual 的 NRMSE 为 0.714%～0.737%，最大绝对差为 8。
这属于需要后续模型质量判定的差异；同调度全状态精确并不意味着跨 Padding 精度准入通过。

每轮实验均保存来源哈希、原始双 rank 报告、同轮对照及 profile；
不能用不同轮次的 Padding 数值拼出收益。

## 优化版完整模型结果

`full-core-join-v3` 已完成。双方统一 NZ，切分使用三组 packed projection 合并，
其他工作量、两步轨迹、四个边界、五轮计时和完整状态核对不变。
仅将不计时的 CPU 审计块从 1M 扩大到 16M 元素，核对的状态范围没有减少。

| B / 默认容量 | Padding 设备中位数 | 提前切分设备中位数 | 设备改善 | 墙钟中位数改善 |
| --- | --- | --- | --- | --- |
| 98 / 400 | 120.330 ms | 119.998 ms | +0.276% | +0.746% |
| 73 / 304 | 111.535 ms | 111.640 ms | −0.094% | −0.001% |

所有十个样本先逐样本取慢 rank，再求平均：

| 口径 | Padding | 等待切分 | 提前切分 | 提前切分相对 Padding |
| --- | --- | --- | --- | --- |
| 设备事件时间 | 116.009 ms | 116.359 ms | 115.818 ms | 改善 0.165% |
| 完整墙钟时间 | 125.445 ms | 125.544 ms | 124.913 ms | 改善 0.424% |

设备时间的因果对照是：切分成本约 0.350 ms，提前启动省约 0.541 ms，净省约 0.191 ms。
五轮设备改善率为 +0.107%、−0.033%、+0.167%、+0.523%、+0.059%，仍有一轮退化。
五轮墙钟改善率均为正，但设备与墙钟幅度不一致，不能把全部墙钟差异归为 NPU 并行收益。
事件起点位于图回放入口，计时覆盖等待准备流、真实更新与最终汇合；
该设备事件时间也不能描述为不含任何等待的纯 kernel 时间。

本轮仅对 B98 做 profile，观察到：

- 每个目标边界输入投影与最后一段通信仍重叠约 114～119 μs。
- 合并相关 ConcatD 总工作从初版约 46～52 μs 降至约 34～35 μs；其中含双方都有的 core 内合并。
- 切分输入 GEMM 为约 268～285 μs，整批约 176～194 μs，小矩阵成本仍是主要损失。
- 每个边界仍有约 18～22 μs 的通信结果写回工作，本轮没有省略这两次拷贝。
- 四个目标边界的局部跨度合计相对同轮 Padding 缩短约 0.145～0.199 ms。
  这与小幅完整模型收益的数量级一致，但 profile 跨度不是无 profiler 计时的替代品。

完整模型可能把一条逻辑主流拆为多个物理 stream ID。
分析器已修正为覆盖所有矩阵乘所在的物理段，并检查每个边界的全部投影是否被包含，
避免将后段 kernel 误判为零开销。CPU 回归测试覆盖了这种情况。

优化版全部模式仍通过连续两步同调度 eager/replay 输出和全状态精确核对；
提前切分与等待切分的最终输出精确一致。跨 Padding 的数值差异指标与初版一致，
没有消除跨形状差异，不能视为模型质量认证。

## 当前判断和下一步边界

已经完成“局部正收益接完整模型；发现成本后再优化一次”的小实验。
当前证据支持：在 B98 的默认容量下，局部请求流水和尽早合并能带来小幅完整模型收益。
当前证据不支持：常规随机动态 batch 普遍更快、达到 5% 级别加速、服务端吞吐提高或质量已准入。
B73 不占优，以及五轮中仍有设备时间退化，都需要保留。

后续的主要目标应是减少拆小输入 GEMM 增加的约 80～100 μs/边界，
而不是继续优化几个事件调用或把现有切分直接扩到所有层。
两次通信结果拷贝也是明确成本，但即便完全去掉，四个边界的收益上限仍只有约 0.08 ms；
仅优化它不能兑现大幅端到端提升。
若继续推进，优先补 B73 的单步 profile，判断它是否因为矩阵形状或窗口大小跨过盈亏点，
再决定是否值得实现让分段结果直接供下一层消费的投影/通信接口。
