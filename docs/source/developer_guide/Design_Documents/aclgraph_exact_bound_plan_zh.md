# 精确规划收紧可行上界：机制、验证与候选结束

日期：2026-10-20。承接[动态描述符候选筛选](aclgraph_dynamic_descriptor_plan_zh.md)。

**本轮精确实现成立，但没有生产者净收益，结束当前共享计划优化候选。**
不接一次规划、16 次消费的小链，不扩完整模型，不增加路由器，
不以简单近似分区继续挽救本候选。

## 1. 本轮实际改了什么

保留原完整头原子、6/10 对齐成本代理、minimax 目标、规范化恢复及全部 1024 字契约。
仅把二分搜索的初始上界从“全部成本之和”，改为“低成本前缀分段的最大段成本”。

```text
本步 host 长度准备
  → 必要 KV 长度 H2D
  → 同一个固定 AIV 核内：成本前缀 → 可行上界 → 精确搜索 → 原规范化恢复 → 完整元数据
  → 最终等待
```

上界在捕获核内计算，没有在 CPU 预先计算本步答案，也没有额外的上界上传。
上界构造和必要长度上传都在生产者端点内。
小型前缀划分只用于构造证书，最终输出不是这个近似分区。

旧 AIV 原型源码和既有报告保持不动，新文件单独保存，便于同进程三方对照。
这里仍是隔离研究算子，没有注册生产模型路径。

## 2. 为什么不会改变精确结果

设完整头成本为非负整数 `c[0..N)`，前缀 `C[0]=0`、`C[i]=sum(c[:i])`，
总成本 `S=C[N]`，有效组数 `P=max(1,min(20,正成本头数))`。

初始下界保持为：`L=max(max(c),ceil(S/P))`。

对 `j=1..P-1`，取前缀等分点 `floor(j*S/P)`，
以 upper_bound 找到满足 `C[e[j]] <= floor(j*S/P)` 的最右位置；
设 `e[0]=0`、`e[P]=N`。
取 `U=max(C[e[j]]-C[e[j-1]])`。

这些端点非递减，覆盖全部原子，成本不重复也不遗漏，因此 `U<=S`。
端点重复或零成本段可以合并，得到至多 P 个正成本连续段。
若正成本原子存在，其数量至少为 P；将部分段继续按完整头细分，
就能得到恰好 P 个正成本段，且最大段成本不会增加。
全零情况由一个完整覆盖段处理，`L=U=0`。

所以该 U 是精确目标的可行上界，满足 `L <= 最优值 <= U <= S`。
在 `[L,U]` 内执行原精确搜索仍能得到相同最优值。
最终端点仅由成本、最优值和原有正原子预留规则恢复，
故仍应逐字得到同一规范化元数据，而非只保证近似负载。

这也是为何不将前缀等分的端点直接交给 consumer：
一次规划的节省只出现一次，分配失衡却会影响后续多次 attention。
本轮没有以牺牲分配质量换取规划时间。

## 3. 正确性与工作量检查

CPU 审计通过 16,221 个小整数成本/核数组合，包含零空洞、全零、单重原子等情况。
每个检查同时验证：可行上界、上界处可规范化为合法分区、精确最优值、
最终端点与原 `_cuts` 完全一致。
原 128 步动态轨迹在默认容量下也全部通过。

两代实际计时输入如下；其余边界输入只用于资格，不拿来报告性能。

| 输入 | 原搜索区间 | 收紧后区间 | 精确最优值 | 原轮数 | 新轮数 |
| --- | --- | --- | ---: | ---: | ---: |
| 原 step 0 | 下界 1804，上界为总成本 | [1804,2012] | 1908 | 15 | 7 |
| 原 step 6 | 下界 1894，上界为总成本 | [1894,2102] | 1968 | 15 | 8 |

单卡 A2/910B3，设备端实际资格范围仍为物理 100 请求、400 token，
Q4/GQA6/KV2/D256/page128、KV 0..4097、20/40 核。
实现的物理 batch 上限仍为 128，但本轮没有资格化其他物理容量。

同一进程捕获 AICPU、原 AIV 和收紧上界 AIV 三张互斥固定图，依次执行。
七代长度的全部 1024 字均与 CPU oracle、原生完整头导出精确一致，
输入内容不被改写，描述符和元数据地址固定；计时后再次全字段检查通过。

另用不参与计时的插桩核检查 `L/U/最优值/搜索轮数/P/S`，全部与 CPU 一致。
正式计时核不写这些诊断计数，也不消费 CPU 的上界或计划。
插桩核的轮数是工作量诊断，不能替代正式核的时间测量。

## 4. 同进程生产者端点结果

测量前声明门槛：四轮交替测试中，每轮设备和 wall 中位数相对 AICPU 均改善至少 3%，
才允许接既有的一次规划、16 次消费小链。

每模式每轮 10 个正式样本，共 120 个；仅交替使用上述两代真实长度。
每个模式都在 wall 内准备本步长度，上传同一份 KV 描述符，回放自己的固定图并最终等待。
设备事件包含长度 H2D、计划与流依赖；wall 另外包含 host 准备、提交和同步。
输出契约、字段覆盖、输入生命周期和最终等待相同。

| 实现 | 设备端点中位数/μs | wall 中位数/μs |
| --- | ---: | ---: |
| 已资格化 AICPU 完整头生产者 | 115.49 | 297.02 |
| 原精确 AIV，初始上界为 S | 186.20 | 371.18 |
| 精确 AIV，收紧可行上界 | 163.05 | 347.75 |

新核相对原 AIV 的设备端点减少约 12.43%，但相对 AICPU 仍慢约 41.18%，
wall 慢约 17.08%。各轮设备和 wall 都退化，没有接近稳定正收益门槛。
本轮基线自身比上轮更快，所以只使用同进程的 115.49 μs 做本轮比较，
不拿上轮的 126.29 μs 混算收益。

这证明收紧上界有实际效果，但“优化了旧原型”不等于“生产者取得净收益”。
没有测试 attention 链或模型时延，因此不存在本轮端到端加速结论。

## 5. 收益空间与失败原因

能确认的事实是：搜索轮数已减少，完整输出未变，但包含构造成本的真实生产者端点仍更贵。
本轮没有删除每轮对全部头的 successor 查找、五层倍增、最终规范化恢复和完整写出。
上界构造还需一次前缀查找、边界成本读取和最大段成本归约。
减少二分次数并不使整个生产者按同比例变快。

每模式另抓一次诊断 replay：长度 DMA 分别约 2.50/2.54/2.52 μs，
AICPU 核 104.34 μs（另有清零 2.30 μs），原 AIV 核 303.23 μs，收紧上界核 244.86 μs。
这条时间线确认剩余主要工作仍在计划核内部，未发现额外的大块上传。
profiler 对 AIV 扰动显著，这些单次核时长不能替换上表的无 profiler 端点，
也不能与另一轮的设备事件相减；依赖 `NOTIFY_WAIT` 不能再加一次。

没有对“上界构造、每轮搜索、恢复、转换”分别做可比的因果消融，
所以不能精确声称某一部分独占了剩余差距，或把所有差距归因于 FP32 gather 兼容转换。
也不能据此否决所有硬件、编译器或所有设备规划算法。
结论限定为当前 A2、受限完整头目标和这两版精确 AIV 原型。

历史共享链的 profile 中，每步只生成一次计划，计划核为 69.12～118.10 μs，
对应 16 次 attention 核合计约 3.77～4.94 ms。
把生产者核理想化为零成本时，其在“计划核 + attention 核”清单中的占比仅约 1.80%～2.39%。
这只是同一历史记录内的乐观清单比例，未计新核、清零、DMA、提交和等待，
不是实测净收益，不是模型加速承诺，也不是通用时延上界。

既有共享已将规划收益摊薄；不能把 69～118 μs 乘 16，
也不能通过每层重新规划、专门容量或隐藏描述符准备来制造较弱基线。
本轮仍有负收益，因此遵守停止条件，结束这个共享计划优化候选。

## 6. 与已有工作的区别与交付

设备描述符、计划/执行分离、AIV 元数据生成均已有社区实现，
具体对照见[已有工作比较](aclgraph_dynamic_descriptor_plan_zh.md#5-与已有工作的区别)。
可行上界收紧精确搜索本身也是通用算法技巧，不能作为独立首创宣称。

本轮可交付的增量是：固定 ACLGraph 下同一完整头 minimax/原生 ABI 的精确实现、
可行性与恢复一致性检查、包含构造和上传的公平负结果，以及据此结束候选的证据。
它目前不能作为毕业设计的高性能注意力创新主张。
对照仍是本分支已资格化的完整头生产者，不是未经修改的官方全功能 FIA。

- `benchmarks/aclgraph_descriptor_bound_kernel.py`：图内可行上界和精确搜索。
- `benchmarks/aclgraph_descriptor_bound_probe.py`：三方固定图资格、端点及独立诊断。
- `benchmarks/aclgraph_descriptor_bound_audit.py`：CPU 证明检查、哈希及稳定收益门槛。
- `tests/ut/worker/multi_graph/test_descriptor_bound.py`：重原子、空分段、非法成本及强基线门槛检查。
- `benchmarks/results/multi_graph_structural/dynamic-descriptor-bound-v1/`：原始报告、审计和诊断记录。

CPU 复算：

```bash
python benchmarks/aclgraph_descriptor_bound_audit.py \
  --producer benchmarks/results/multi_graph_structural/dynamic-descriptor-bound-v1/producer-result.json
```

没有升级驱动、镜像或修改生产模型路径。新的总体研究目标仍保留；
本轮结束的是这个具体共享计划候选，不是已经完成了动态形状优化目标。

本轮 25 项 CPU 单元测试、16,221 组穷举与原轨迹审计、限定 Ruff 检查均通过。
仓库要求的 `bash format.sh ci` 已尝试，仍被本机 WSL/CRLF 阻断，日志保存；未宣称完整 CI 通过。
