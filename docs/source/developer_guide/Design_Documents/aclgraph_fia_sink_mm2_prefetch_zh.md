# MM2 跨块预取实验

## 1. 要解决的等待

MM2 计算注意力概率 P 与 V 的乘积。原循环处理每个 64 行块时，先搬 P 并等待，
再搬 V 并等待，然后加载 L0、计算、经过 Cube 屏障，才开始下一块搬运。
即使 L1 有多个槽，这个发射顺序也可能让搬运与计算难以重叠。

本实验保留原 Q/V 分配、固定步长描述符、三个 KP 槽和两个 V 槽。
不再调整槽位大小，不扩大搬运块，也不改变 64 行计算顺序。
唯一目标是将下一块 P/V 搬运发射到当前块 Cube 屏障之前。
这能否缩短真实等待，需要设备测量；发射顺序变化本身不证明加速。

## 2. 实现与边界

1. 等待原 `syncV1C2`，确认 Vector 已完成当前任务的完整 P 写入。
2. 搬运块零：分别取得 KP/V 原空闲事件，搬运并设置就绪事件。
3. 每块消费自己的两个就绪事件，按原参数加载 L0，并发起矩阵乘。
4. 若当前不是尾块，将下一块搬入下一组 KP/V 槽，然后执行原 Cube 屏障。
5. 保留原槽位释放、环索引、输出和跨核同步；尾块不预取额外数据。

预取只发生在当前任务内，不跨任务、请求、工作区环周期或图回放。
每个槽仍须取得原空闲事件，包括刚被 MM1 使用过的 KP 槽。
每个真实块只搬运一次、计算一次。所有必要真实长度更新、最终等待均保留。

当前门槛限定 A2、BF16、TND、paged BSH、Q4/GQA6/KV2/D256、page128，
无 sink/RoPE/uniflag、预装载任务数为二、S2 块不超过 512。
任务实际 M 必须为 1～64，实际 K 为 1～512，确保只有一个 M 块和每块一个 L0 乘积。
不满足门槛时保留原循环。实验二进制仅包含两个既有分块键，
不能把源码回退能力当成任意形状的二进制资格。

## 3. 验证安排

- 用原生 Axis 和实际修改后的完整 MM2 方法执行 CPU 事件模型。
  检查 1～512 的所有尾块、所有 KP/V/L0/C 环起点、ND/NZ 格式、连续三次任务调用，
  与原方法比较搬运参数、计算顺序、最终索引、快照和事件余额。
- 用宏零、宏一独立构建，同样布局和同样两个分块键，隔离部署。
- 在原 B98/cap400、B128/cap512 两条记录运行 A→B→B→A 四个独立进程。
  每容量预热五次、常规计时十次、单独剖析一次，保留 FP32 抽样、完整输出哈希和计划核对。
- 比较正反顺序，并将常规端点与注意力剖析分开；失败或退化同样保存。

CPU 模型只验证发射顺序与令牌所有权，不能证明设备异步安全或性能。
源码中的同步位置也不能单独证明硬件实际串行等待。
筛选要求两个容量在正反顺序都改善，且单独注意力剖析方向一致，才继续资格验证。
若均值受慢样本主导，或正反结果不一致，则保留结果、不扩大矩阵。
四进程小实验本身不能建立稳定的总体收益或统计置信结论。

## 4. 与已有工作和图切分的关系

双缓冲、搬运预取和计算重叠是已有算子流水线方法，不能写成算法首创。
本项是针对当前 A2 FIA sink、D256 容量限制和原任务生命周期的具体适配实验。
没有开展新的全面查新，也不声称研究优先权。

它属于填充和切分都可采用的共同算子优化，不能直接证明切分必要性。
若有效，应给填充和切分相同的执行算子，再判断切分调度本身的收益。
当前证据仍是十六次合成注意力链，不代表真实模型或 serving 收益。

## 6. 这次实验排除了什么，下一步查什么

两条记录按源码和真实描述符推导，每次注意力分别有 3048/4268 个 MM2 小块，
其中 2582/3626 个存在下一块可预取。这是源码推导，不是设备分支计数。
预取机会充足仍未带来净收益，说明“只把下一块搬运提前”不是当前已成立的优化点。
不能据此证明全部预取方法无效，也不能将退化直接归因于某一个流水线冲突。

随后另做两个诊断进程，只增加 Level1 / PipeUtilization 采集，
没有重复完整性能矩阵。修改仅涉及剖析配置和输出回调；输入、二进制、计划和完整输出
均与正式对照一致。诊断产生的单次常规计时不参与性能结论。
四组剖析各含十六个注意力、一个计划生成器和一个清零任务；
148 个文本原始文件逐字节核对通过，详细数值见
[硬件计数审计](../../../../benchmarks/results/multi_graph_structural/fia-sink-mm2-prefetch-v1/counter-audit.json)。

不同管线可以重叠，比例不能相加成开销占比，也不等于 HBM 带宽使用率。
观测线索是：候选的 MAC 和 MTE1 时间基本不变，标量活动每次增加约 5.69/6.26 µs，
MTE2 时间未下降。**只调整预取发射顺序没有减少标量工作和数据搬运。**
硬件指标覆盖整个注意力调用，仍不能直接定位 MM2 的某一条事件；
每版一个诊断进程不能建立根因或稳定指标差异的结论。

下一项优先核查实际标量寻址路径：当前 `ProcessPageAttention` 对每次小块搬运调用
`GetOffset`，后者解析页内坐标并经 `BlockTableParser::GetBlockIdx` 读取页表。
对应原生源码已保存至证据的 `source-followup` 目录。
先检验能否在同一任务内复用页索引或页基址，减少相邻 64 行块的重复解析，
同时保留真实页表更新、原搬运范围和计算次序。
这只是有硬件线索支持的下一项消融，尚未实现，也没有确定性能收益；
不能据此宣布注意力已受带宽限制，更不能宣称切分会超过填充。
