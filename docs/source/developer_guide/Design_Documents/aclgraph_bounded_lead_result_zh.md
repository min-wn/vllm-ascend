# 请求分组有限领先：闭合段小实验与瓶颈分析

日期：2026-10-19。

## 1. 结论

**跨层提前执行有效，但本实现尚未超过 Padding。**
三轮独立设备计时中，相同切分算术只改变依赖，提前执行节省 140.79～165.18 微秒；
相对 Padding 仍慢 77.36～94.86 微秒，即 2.72%～3.34%。
这是前层 MLP 到下一完整 GDN 层的闭合段结果，不是全模型或服务端收益。

时间线进一步说明：被前层最后一块归约隐藏的只有下一层 A 组输入 Norm 和投影，
GDN core 开始时该归约早已结束。继续把 core 切两份增加了重复工作，
本次没有换来 core 与前层通信的重叠。
下一候选因此是**只拆需要提前的输入投影，在 GDN core 前重新合批**。
这是一项基于本次 profile 的具体假设，尚未实现或证明能够超过 Padding。

## 2. 对照、容量与计时范围

机器为 910B3 双卡；Qwen3.5-27B BF16、TP2、Q4。
使用已有种子 20261016 选出的 B98；默认图容量 400 个词元，切分为合法的 200+200。
每个请求四个词元，所以两个物理分支各容纳 50 个请求，真实请求分配 50+48。
没有新增 49 或 98 专用捕获容量，没有切分 attention head。
Q4 是单次验证形状，不运行 draft model 或估计接受率吞吐。

本次使用真实第 3 层 MLP 与第 4 层 GDN 的权重、卷积及紧凑状态。
入口是合成的、视为已完成 attention O 归约的 hidden/residual，
出口包含下一层完整 O、MLP、所有 TP 归约、状态提交和最终流汇合。
前一层 FIA 与其 update 不在这个端点内，不能据此宣称省去了真实推理的 update。

| 路径 | 执行方式 |
| --- | --- |
| Padding | 整批前层 MLP → 整批下一层 GDN，包括其 MLP。 |
| 切分等待 `split_barrier` | 共享前层 GateUp/激活；拆 Down/归约；等两块归约完成；分别执行下一层输入投影/core；O 前合批。 |
| 提前执行 `split_early` | 算术与上一行相同；A 归约完成即可开始 A 的下一层输入投影/core；O 前合批。 |

两块前层 Down GEMM 都先于下一层 GEMM，不用下一层 Cube 计算争抢前层 Down。
切分的 HCCL 顺序固定为 Down A、Down B、下一 O、下一 Down，两个 rank 相同。
三个控制都使用 NZ 权重、同一 ready-tile compact recurrence。
分支独立 scratch/事务，只为不相交请求共享规范状态；没有复制额外 attention 权重。

每模式三轮、每轮六个有效样本，轮间正反交替模式顺序。
先逐样本取双 rank 较慢值，再计算轮内中位数。
输入刷新复制在图内；元数据准备和快照恢复在计时外。
每次计时前恢复相同一致状态，动态连续状态另做三步资格检查。
因此计时不是连续服务动态轨迹，也未覆盖元数据构建的主机开销。

## 3. 独立计时结果

单位为微秒；以下均为每轮慢 rank 样本的设备时间中位数。

| 轮次 | Padding | 切分等待 | 提前执行 | 提前执行比切分等待减少 | 提前执行比 Padding 增加 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 1 | 2843.37 | 3085.91 | 2920.73 | 165.18 | 77.36（2.72%） |
| 2 | 2838.26 | 3083.39 | 2933.12 | 150.27 | 94.86（3.34%） |
| 3 | 2845.97 | 3074.34 | 2933.55 | 140.79 | 87.58（3.08%） |

墙钟同方向：Padding 2972.12～2983.93，提前执行 3052.71～3071.87，
逐轮慢 2.55%～3.36%。六样本/轮只用于小规模筛选，不宣称尾延迟或统计显著性。

切分等待仍允许 Down B 与 Down A 通信重叠；它不是全串行切分。
因此与提前执行的差值更直接反映“下一层消费者不用等整个 batch”的收益。
它并不代表切分相对 Padding 的收益。

## 4. Profiling 找到的瓶颈

每模式每 rank 单独抓一份 replay，共六份 trace。
算子数量与设计一致：Padding 7 次 MatMul、3 次归约、1 次 solve/commit；
切分 10 次 MatMul、4 次归约、2 次 solve/commit。
所有 trace 均确认下一层输入 GEMM 不早于前层 Down B GEMM 完成。

提前执行的 Down B 归约为 142.16～143.42 微秒，
A 输入 GEMM 与其重叠 121.32～124.48 微秒；
加上输入 Norm，主计算流覆盖该归约约 142.10～143.34 微秒。
A 的 solve 在归约结束后 161.56～164.28 微秒才启动，重叠为零。
这支持“输入投影用了窗口、core 分裂没用到这个窗口”的判断。

| 局部工作量，双 rank 范围 | Padding | 提前执行 | 解读 |
| --- | ---: | ---: | --- |
| 下一层输入 GEMM 总时长 | 172.08～173.04 | 248.50～249.44 | 小矩阵投影约增加 76 微秒。 |
| GDN solve 总时长 | 254.03～259.10 | 273.53～273.74 | core 本体约增加 15～20 微秒。 |
| Down 完成到下一 O 之间，主流非 GEMM/非 solve 工作 | 243.11～245.74 | 427.36～436.89 | 按同 rank 比较增加 181.62～193.78 微秒，是主要额外工作。 |
| commit 总工作时长 | 51.98～52.68 | 97.84～98.84 | 大部分与其他工作重叠，不能全部算入关键路径。 |

第三行包括输入 Norm、卷积、切片、清零、转换、gating、归一化和合批等。
O 前额外两次显式拼接合计约 24.60～25.60 微秒，
因此仅删除最后拼接不足以弥补 77～95 微秒差距。
A commit 与 B 输入 Norm 的时间线重叠，后者约 37～38 微秒；
这提示可能存在干扰，但本实验未单独隔离其因果贡献。

以上为工作量诊断，不能直接把表中差值相加当作可兑现加速。
不同流有重叠，分组也改变了 kernel 配置、缓存及资源竞争。

### Profile 的限制

三份 profile 的首个 collective 出现约 2.03、6.48、13.18 毫秒等待，
与相邻另一 rank 不对称，说明 profiler 阶段存在明显到达偏差。
现有证据不能将其进一步精确归因到某个 profiler 初始化调用。
**不将这些总跨度或首归约耗时用于性能、链路成本和收益估计。**
独立计时发生在 profiler 之前；本结论的净收益取自独立计时。
profile 仅用于每个 rank 内的依赖、重叠和局部 kernel 工作诊断。

## 5. 正确性与尚未证明的事项

双 rank、三条路径均完成 B98→97→99、接受前缀 1→2→3 的连续三步检查：
同调度 eager/replay 输出和状态严格相等；切分等待与提前执行严格相等；
inactive/null 状态不变，初始化 dense source 不写回，输出与状态均有限。

切分与 Padding 改变矩阵形状，存在跨形状数值差异。
hidden NRMSE 为 0.00413～0.00458，最大绝对差 0.0625；
residual NRMSE 为 0.00154～0.00164，最大绝对差 0.5～1.0。
按原阈值 `0.02 + 0.02 * abs(reference)`，residual 三步分别有 4、3、3 个元素失败，
其余记录字段通过该阈值。两个 rank 的诊断一致。
没有放宽阈值，也没有把同调度精确一致写成模型质量已验证。
本轮不能单凭“BF16 正常误差”宣称这些跨形状差异一定可接受。

## 6. 下一步如何调整，而不是继续加流

已有证据支持把候选改为：

```text
整批前层 GateUp/激活
    → Down A/B 计算 + 有序归约
    → A 输入 Norm/投影提前（覆盖 B 归约）
    → B 输入 Norm/投影
    → 合批投影结果/残差
    → 一次整批卷积、GDN core、gated Norm、commit
    → 整批 O、MLP
```

与当前 O 前合批不同，这条候选在 core 前合批。
与过去“共享输入投影后切 core”也不同，这次保留能提前的投影切分，
合并没有利用到跨层窗口的 core。
它仍是请求切分产生的细粒度依赖优化，不依赖减少合法填充容量。

后续应先检查投影结果的整批布局接口：普通 `cat` 需要复制 mixed-QKV、z、b、a 和 residual，
不能将重新合批视为零成本；若改为固定整批输出缓冲区的分块写入，
还需解决投影输出接口、步幅、覆盖完整性与图地址稳定性。
合批后用 full metadata 执行一次 core/commit，仍需保持请求 ID、卷积状态和接受前缀一致。

筛选门槛很具体：包含新增合批成本和完整汇合后，相比当前提前执行至少追回约 95 微秒，
才有希望在本次三轮条件下全部超过 Padding。这个数字不是未来运行的保证或置信界。
现有 profile 显示可研究的重复工作量，但尚未建立可兑现的净收益预算。
若布局改造把可节省工作抵消，应停止此候选，不扩大分支数或模型矩阵。

本轮不再增加 NPU 运行，先保留这些证据供下一次针对性实现使用。

## 7. 与已有工作及毕设贡献的边界

请求微批、通信计算重叠、跨层流水和选择性合批本身不能声称首创。
整批 GEMM 内部提前发布、通信融合等公共优化仍须同步给 Padding。
本次只验证了当前实现中消费者提前执行的因果收益和其成本位置。

可继续研究的问题是：**根据真实通信窗口，自动确定哪些请求分组工作必须拆、
在哪个算子前合并，以最少重复工作缩短最终完成时间。**
这次为“汇合位置不能预先固定在 O”提供一条具体负结果和修改依据。
尚未形成经过文献创新性核对的算法，也没有新的端到端正收益。
历史反证与外部工作的归因边界见
[请求切分依赖理论](aclgraph_split_dependency_theory_zh.md)。
