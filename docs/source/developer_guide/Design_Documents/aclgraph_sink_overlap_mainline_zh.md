# 页地址消融与下一条性能主线

更新：2026-10-19。本文区分已经测量的结果、待验证机制和毕设贡献边界。

## 当前决定

停止扩大页地址复用、槽位大小和预取类微调。下一候选是：
**设备端计划驱动的请求块就绪调度，联合优化 attention 与 FFN 的执行边界。**
先证明资源重叠值得做，再实现真实依赖；不是直接启动完整模型大改。
现阶段没有证明此候选超过 Padding，也没有新取得完整模型收益。

这个方向的目标是让一部分请求完成 attention 后可以向后推进，
而不必等同批其他请求完成；同时避免把大 FFN 拆成多次低效的小 GEMM。
它需要切分的是任务的依赖与完成粒度，不要求为每个请求块添加图容量。
输入可以动态变化：固定图地址，设备描述符提供当前请求身份、长度、页表和有效任务。

## 已完成：页地址复用未通过性能筛选

原 MM2 在 D256 下每次搬运 64 行，而 KV 页有 128 行。
候选只在一次 ComputeMm2 内保存当前 V 页地址，下一半页用行偏移递增。
不改变 L1 分配、搬运量、矩阵计算顺序或事件协议。
门槛包括 A2、BF16、TND、BSH、page128、Q4/GQA6/KV2/D256、
单 M 块、512 行任务起点，无 sink/RoPE；其他情况回到原 CopyVToL1。

| 顺序 | 原始记录／物理 token 容量 | 原版均值 µs | 候选均值 µs | 均值改善 |
| --- | --- | ---: | ---: | ---: |
| 原版→候选 | B98／400 | 4267.212 | 4396.854 | −3.038% |
| 原版→候选 | B128／512 | 5374.696 | 5562.109 | −3.487% |
| 候选→原版 | B98／400 | 4210.335 | 4296.541 | −2.047% |
| 候选→原版 | B128／512 | 5336.676 | 5366.964 | −0.568% |

负数表示变慢。每个单元 10 次计时、独立性能剖析；端点包含 pinned 描述符准备、
必要 H2D、计划生成、16 次私有合成 attention 和最终等待。
80 个计时全部保留，144 行 FP32 抽样通过，四进程完整输出哈希一致。
关闭宏的编译对象与此前真正原版逐字节相同。

CPU 执行实际新 helper、原 CopyVToL1、原分页拷贝及 GetOffset 方法，
以记录 DMA 参数的方式核对 331776 个任务实例，覆盖全部 1..512 尾块、
两槽起点、不同请求/头/任务索引与三代变化的页映射。
这证明该受限域的源地址和搬运参数一致，不证明硬件异步语义。
实际设备检查另外完成；未推广候选。

减少源码页查询不等于减少 HBM 数据量，新增分支和持久标量也有代价。
当前反汇编工具不能解码该对象的指令，不能宣称已证明编译器保留哪些冗余计算，
也不能将全部退化归因于单一寄存器或分支因素。

## 已完成：sink 与 FFN 的乐观并行资格实验

为什么重新检查：早期 Qwen3-4B 的独立 FFN/FIA 资源实验有固定图局部信号，
但真实 host update 使 FIA 就绪过晚；完整请求流水最终未超过 Padding。
目前设备 sink 计划改变了启动路径，值得重新测一次，但旧负结果仍然有效。

本轮使用原始容量 400、两条原轨迹的同容量记录；真实长度与页表每步 H2D。
attention 为一份私有 BF16 合成 QKV，Q4/GQA6/D256。
FFN 为 Qwen3.5-27B 第 3 层真实 rank0 TP2 权重切片，
5120→17408→SwiGLU→8704→5120，权重 NZ，输入为独立就绪的随机张量。
四个图共用同一份权重，不增加 attention 权重副本。

**重要边界：attention 和 FFN 各自处理 400 行，它们不是同一个 400 行 batch
的两个互补子集。实验没有真实 FFN 输入依赖、TP collective、QKV 生成、KV 写入，
不是完整 decoder，不是切分对 Padding。**
它只能检验现有硬件和算子是否还存在可利用的并发空间。

每进程四轮，每轮每模式 3 次预热、10 次计时，轮间反转顺序；
第二进程反转图创建顺序和首轮顺序。计时包括描述符准备、必要 H2D、
设备计划、attention/FFN、图汇合和最后等待。profile 另采。

| 进程 | 全核串行 µs | 全核并行 µs | 中位数改善 | 半核串行 µs | 半核并行 µs |
| --- | ---: | ---: | ---: | ---: | ---: |
| 首轮 | 1279.081 | 1207.730 | 5.578% | 1833.673 | 1466.971 |
| 反向复测 | 1267.611 | 1185.224 | 6.499% | 1813.978 | 1463.421 |

半核并行必须和全核串行比较，不能拿受限串行的低性能夸大收益。
两进程 320 个计时与各自独立 trace 保留。所有模式都通过完整 attention 输出
对原 sink 输出、FFN 对 ND 权重计算的容差比较和计划覆盖核对。
首轮只有计时前输出核对；第二轮另外补充计时与 profile 后核对。
这不是模型精度、长序列状态或多卡通信资格。

首轮 profile 的并发 attention、GateUp 和 SwiGLU 时间明显延长。
因此硬件确实重叠，但竞争同样明显；profile 数值受剖析影响，
不得用它替换无剖析计时或把不同管线时长相加。
还需区分局部收益来自规划与 FFN 重叠，还是来自真正的计算互补。
为此另做下节的计划阶段消融，不能直接将 5.6%～6.5% 归因于 attention/FFN 算子互补。

## 因果消融：先区分计划隐藏与计算重叠

四种控制保持同样输入、数据类型、FFN 权重与每步真实计划：

1. 完全串行：计划→attention→FFN。
2. 原并行：计划→attention 与 FFN 同时起步。
3. 只隐藏计划：计划与 FFN 并行，FFN 完成后再做 attention。
4. 计划先完成：计划后同时开始 attention 与 FFN。

若只有控制 3 有效，优先利用计划提前执行，不建设复杂并行算子；
但计划本来跨 16 个兼容层共享，这个收益预算很小，且 Padding 同样可用。
若控制 4 仍有稳定收益，再讨论请求块级流水，且须先计入切分 GEMM 的损失。

追加单进程四轮消融已完成，每模式 40 个计时，结果为：

| 控制 | 中位耗时 µs | 相对完全串行改善 |
| --- | ---: | ---: |
| 完全串行 | 1264.215 | — |
| 原并行 | 1178.149 | 6.81% |
| 只隐藏计划，attention 与 FFN 串行 | 1203.740 | 4.78% |
| 计划先完成，再并行计算 | 1238.921 | 2.00% |

它收紧了之前的判断：相当一部分可观测改善在不重叠 attention/FFN 计算时
也能出现，不能把原来的 5.6%～6.5% 全部归为算力/带宽互补。
几项差值不是可相加的独立开销，控制 3 同时改变了 attention/FFN 的先后顺序，
因此只提供机制筛选证据，不是精确因果百分比分解。
控制 4 的约 2% 仅一个进程，不足以支持完整模型大改。
每个控制均保留设备计划；没有把真实计划移出计时。

因此下一步先做关键路径预算与就绪协议的可行性检查，
不直接把普通双流扩展到全模型。大收益主线仍是候选，尚未成立。

## 如何成为更大的主线：明确机制，而不是更多流

候选机制包含三个部分，目前未实现：

1. **设备任务计划与有效请求绑定。** 请求行块仍来自既有默认图容量。
   计划显式保存实际行范围、KV 区间、输出归属和就绪代号，
   每步刷新真实描述符；不沿用过期页映射或省略长度更新。
2. **按块发布完成状态。** attention 完成一个请求行块的完整归并后，
   才发布其结果就绪。下游必须依赖完整 O 投影、TP 归约、残差和归一化，
   不能把 attention 内部部分和当成最终 FFN 输入。
3. **保留大 GEMM 的块调度。** 研究在一次大矩阵算子内部消费就绪行块，
   保留原 TP 权重切片及权重复用。禁止退回“每块重新启动一次小 GEMM”。
   发布/等待、缓存可见性、任务优先级和有界工作区均需独立资格验证。

与目前原型区别：目前只有整算子级 fork/join；此前公开 ready-tile 路线
已有完整模型结果。新候选要证明的是动态请求块跨这些边界提前推进的额外收益，
必须给 Padding 同样的公开 ready-tile 算子后再比较。
不会复制 attention 权重，不要求修改默认 capture sizes。

### 工程门槛与停止条件

- 不允许占满全部核心的消费者自旋等待尚未获得执行资源的生产者。
  A2 的 stream quota 也不能当作独占物理核心保证。
- 不直接使用未经当前驱动验证的跨核 flag 或持久队列协议。
  先用小型生产/消费任务验证可见性、进度、图重复回放与代号换代。
- 下一真实依赖实验应只做两个 decoder block，包含 QKV、KV 写入、
  attention、O、残差、FFN 和必需 TP 通信；同时比较 Padding、同切分串行、
  同切分就绪推进。每一条依赖都必须有效，不能再使用独立预备 FFN 输入。
- 优先评估当前公开 ready-tile Padding 关键路径可隐藏区间的并集。
  不能把这次独立热权重的每层差值直接乘层数。
- 当前公开全模型均值约 143.474 ms，5% 需要约 7.174 ms。
  本轮每对只观察到约 71～82 µs 差值，即便粗略乘 16 也仅约 1.1～1.3 ms；
  这个乘法只是说明量级不足，不是模型预测。
  **只有 FIA 16 层的局部互补，不足以支持“大幅端到端收益”的承诺。**
- 若想达到较大收益，须在真实预算中证明机制能覆盖更多 GDN/FFN/通信边界，
  或另一条方案能减少主要工作量。若做不到，收缩结论，不扩大完整矩阵。

## 与已有工作的区别

- [NanoFlow](https://arxiv.org/abs/2408.12757) 已研究纳米批流水与资源干扰；
  “attention 与 FFN 并行”本身不是我们的发明。
- [POD-Attention](https://arxiv.org/abs/2410.18038) 针对混合 prefill/decode 的
  算子内资源调度，不能直接套用到当前纯 Q4 的 A2。
- [FlashInfer](https://arxiv.org/abs/2501.01005) 已有固定网格的计划/执行分离，
  官方 sink 同样有设备计划与跨层共享。本项目不能把这些写成新贡献。
- [Hydragen](https://arxiv.org/abs/2402.05099) 与
  [Cascade Attention](https://flashinfer.ai/2024/02/02/cascade-inference.html)
  通过共享前缀分解减少重复 KV 读取，潜在收益较大，但依赖共享前缀。
  当前原轨迹采用请求私有页，不能凭空假设有共享数据来证明一般动态 batch 优势。
- [KIVI](https://arxiv.org/abs/2402.02750) 等 KV 量化能直接减少数据量，
  但需要新增质量验证，且双方均可使用；不是切分独有收益。

可能的毕设贡献是：在 A2 固定 ACLGraph 地址、动态请求描述符、TP 不复制权重的
约束下，设计可验证的就绪块协议，并将并发干扰和 GEMM 复用损失纳入调度。
这是研究候选，不是已证实的新颖性或性能结论。若性能预算不成立，不以移植量充当创新。
