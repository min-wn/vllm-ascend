# 保留双 V 缓冲的 MM2 搬运分块实验

日期：2026-10-19。

## 这次解决什么问题

上一轮将 V 的两个小槽合为一个大槽，减少了搬运批次，但设备实测变慢。
当时同时改变了搬运分块和缓冲数量，无法区分两个因素。

本轮借用 Q 预留但未使用的 L1 空间，给 V 增大槽位，仍然保留两个槽。
然后用三组对照分别判断布局代价、搬运分块的影响和相对原实现的最终效果。

| 版本 | Q 区 | V 区 | MM2 的 L1 搬运 | L0 计算 |
| --- | --- | --- | --- | --- |
| A：原布局 | 两槽，各 96 KiB | 两槽，各 32 KiB | 64 行 | 64 行 |
| B：新布局控制 | 两槽，各 64 KiB | 两槽，各 64 KiB | 64 行 | 64 行 |
| C：新布局候选 | 两槽，各 64 KiB | 两槽，各 64 KiB | 128 行 | 64 行 |

三者的 L1 总量均为 464 KiB，KP 三槽和 K-sink 两槽不变。
必要 K/V 字节、MM1、softmax、计划、图容量和计算顺序不变。
原生 MM2 使用同一组槽位和事件协议，但每组搬运包含的工作及组数改变，
因此不能预先假定流水线重叠一定改善。

## 为什么 Q 可以缩小，以及如何防止错误使用

在受限的 D256、无 RoPE 路径中，MM1 最大 Q 子块为 128 行，
按 256 列 BF16 计算需要 64 KiB。实际 Q4/GQA6 请求的 M 为 24，
对齐后为 32，仍在这一上界之内。
Q 的 NZ 布局采用实际对齐行数作为步长，Load3D 内部继续分两次加载 128 列。

布局选择在整个缓冲分配前完成，包含 A2、BF16、分页 TND/BSH、非 S2=1024 模板、
PRELOAD=2，以及 D256/Q4/Q12/KV2/GQA6/page128、无额外 sink/RoPE 等条件。
条件不满足时，Q/V 分配和槽位步长都回到原值。
不能只关闭 128 行搬运，却仍让不合格输入进入缩小的 Q 槽。
当前二进制仍只包含原有两个受限分块键；源码具有回退不等于任意形状已经获得设备资格验证。

原 `Array<LocalTensor, count, stride>` 的槽位步长是编译期常量。
新布局需要运行时选择完整布局，因此采用显式的两个 LocalTensor 描述符绑定槽位地址。
这可能增加描述符或初始化代价，B/A 对照将一起检查，不能忽略。

## 最小实验和检查范围

顺序固定为 A→B→C→C→B→A，六个独立进程。
沿用原始 step0/B98 和 step29/B128，对应默认物理词元容量 400/512；
没有添加特殊图桶，没有减少必要描述符更新。

每个进程使用相同种子和 16 份私有合成 Q/K/V，预热 5 次，
每容量计时 10 次，并单独剖析一次。
总计 120 次常规计时，216 行 FP32 抽样，36 次完整计划检查。
计时覆盖准备、必要 H2D、真实设备计划生成器、图回放和最终等待。
两种相反顺序分别报告，所有样本保留。

原生 CPU 检查直接编译实际补丁片段和原生 Axis：

- 16 组运行时布局，包括逐项拒绝不合格几何。
- 7 组编译期条件不满足时的回退。
- Q 的 128 种尾块、NZ 地址和两个槽位边界。
- 1026 组长度/是否 sink 的组合，核对计算顺序、尾块、首尾标志和 L1/L0 容量。

CPU 地址检查不证明设备同步安全。设备还需检查完整输出哈希、FP32 抽样、
精确零填充、计划 1024 字、输入只读、地址稳定及实际任务轨迹。
两份新算子均隔离构建，不安装系统包，不覆盖旧实验。

## 结果与决定

六个进程全部完成。下面的正数表示耗时下降，负数表示变慢。
容量 400/512 是词元数，分别对应原始 B98/B128 请求，不能当作请求数。

首先比较相同新布局的 B/C，隔离 64→128 行搬运的影响：

| 顺序 | 词元容量 | B 均值 µs | C 均值 µs | 均值下降 | 中位数下降 |
| --- | ---: | ---: | ---: | ---: | ---: |
| B→C | 400 | 4332.963 | 4274.847 | 1.341% | 0.839% |
| B→C | 512 | 5493.786 | 5390.710 | 1.876% | 1.887% |
| C→B | 400 | 4435.973 | 4296.353 | 3.147% | 3.080% |
| C→B | 512 | 5666.426 | 5410.202 | 4.522% | 3.451% |

这说明同一双缓冲布局中，扩大搬运分组在本轮正反顺序都观察到改善。
但 B 本身可能付出了布局/描述符实现代价：B/A 的四组中位数差值分别为
+0.130%、−1.755%、−2.724%、−4.326%；四次单独剖析的注意力总耗时也均增加。
目前没有将缓冲位置、动态布局条件和显式 LocalTensor 描述符的成本分别消融，
不能将 B 的退化归因于其中某一项。

因此必须继续看 C 相对真正原布局 A 的最终差值：

| 顺序 | 词元容量 | A 均值 µs | C 均值 µs | 均值下降 | 中位数下降 | 单独剖析中 C 的 16 次注意力总耗时增加 µs |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| A→C | 400 | 4517.574 | 4274.847 | 5.373% | 0.968% | 32.921 |
| A→C | 512 | 5405.466 | 5390.710 | 0.273% | 0.164% | 83.542 |
| C→A | 400 | 4352.247 | 4296.353 | 1.284% | 0.440% | 30.280 |
| C→A | 512 | 5440.981 | 5410.202 | 0.566% | −0.726% | 77.921 |

第一组 A 包含 5866.905 µs 的较慢样本，全部保留。
因此不能把该组均值下降 5.373% 当作稳定收益；其中位数仅下降 0.968%。
反向顺序的容量 512 中位数退化，单独剖析的四组注意力总耗时也没有改善。
剖析与常规计时的执行环境不同，只作诊断，不能混入同一组延迟样本。
当前证据不足以把候选推广为可靠优化，也不足以做统计显著性或长期尾延迟结论。

本轮决定是：**保留候选和三组消融证据，不替换原布局，不扩大完整轨迹或模型矩阵**。
它收窄了问题：扩大搬运分组相对新布局控制组有改善，
但新布局相关成本、噪声及未测清的流水线行为，使相对原实现的净收益不足以成立。
这比仅比较 B/C 后宣称获得 1%～4% 优化更严格，也不能反推上一轮退化完全来自单缓冲。

正确性和证据检查：

- 120 次常规计时和 12 次独立剖析全部保留。
- 216 行 FP32 抽样通过，最大绝对误差为 0.00029981881380081177。
- 两个容量下，六个进程的 16 份完整 BF16 输出哈希均相同，且计时前后不变。
- 36 次完整计划核对通过，包含 12 次捕获前检查和 24 次计时前后检查。
- 运行时算子目标文件哈希与对应构建一致，三版本二进制不同，计划生成器相同。
- 独立重算脚本直接读取原始样本，用十进制算术复算全部均值、中位数和 12 个对照差值。

证据位于 `benchmarks/results/multi_graph_structural/fia-sink-mm2-double-buffer-v1/`。
采集的 121 个文件均已核对哈希，仓库保留其中 117 个原始文件及原始清单。
三个算子目标文件和 CPU 检查可执行文件未入库，大小和哈希记录于
`omitted-binaries.json`；仓库复核不声称能够重新读取这四份二进制文件。

在仓库根目录可以复核，输出文件须尚不存在：

```bash
python benchmarks/results/multi_graph_structural/fia-sink-mm2-double-buffer-v1/tools/saved_audit.py --output /tmp/mm2-double-audit.json
python benchmarks/results/multi_graph_structural/fia-sink-mm2-double-buffer-v1/tools/recompute.py --output /tmp/mm2-double-recomputed.json
```

主审计完成 1830 条断言，定向 CPU 测试 73 项通过。
可编辑代码、中文文档和两个复核脚本的 Ruff、拼写、Markdown 与导入检查通过。
全仓格式检查仍未通过，包含冻结源码/脚本快照的格式和拼写项、既有导入项，
以及 Windows 下脚本入口失败。检查器改动的 28 个文件均恢复到检查前字节，
随后重新审计原始证据；不能为通过格式检查而修改实测快照。
完整日志采用 gzip 无损压缩，避免后续拼写检查递归扫描旧日志；解压字节哈希见 `format-log.json`。
日志和检查状态分别保存在 `format-ci.log.gz`、`format-checks.json` 与 `scoped-validation.json`。

## 与已有工作、图切分和毕设的关系

分层分块、双缓冲、片上存储重新分配均为已有算子设计方法。
本实验的具体工作是检查当前 A2/D256 安全适配中搬运和计算的绑定，
并在严格布局门槛下拆分两个因素，不能据此声称新的注意力算法。

该修改可以同时用于填充和多图切分，**不是图切分独有的优化**。
若它有效，将成为双方共同基线；后续仍须单独证明切分创造的执行机会。
若它无效，保留负结果，停止扩大该变体的性能矩阵。

后续若继续该算子路径，不再枚举更多槽位大小。
源码中当前 MM2 先搬 P 并立即等待，再搬 V 并立即等待，然后加载和计算。
保留两个槽位不等于已经实现了跨搬运组的显式预取。
更有意义的下一项是先核查：能否在当前组计算期间，将下一组 P/V 提前搬到空闲槽位，
以流水线重排隐藏搬运等待，而不是仅减少搬运调用数。
这需要重新证明 KP/V 槽位所有权、Vector 产物就绪与跨任务生命周期，
并测出等待时间和可重叠窗口；当前尚无该实现或收益保证。

当前约 1.79% 的完整动态描述符轨迹改善仍来自此前的调度策略，
其中存在负轮次和 P99 退化，且仅为合成注意力链。
本轮不能与它相加，也不提供真实模型或在线服务收益结论。
