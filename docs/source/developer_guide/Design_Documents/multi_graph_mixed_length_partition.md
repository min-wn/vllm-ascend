# 混合 KV 长度与请求分组实验

2026-10-17。承接 [结构优化计划](multi_graph_asymmetric_pipeline.md) 第二阶段。
第一阶段完整 FFN 流水已停止扩大；本阶段恢复共享 O/FFN，仅切分 attention。

## 待验证的问题

相同请求集合与总 KV token 数下，FIA 是否存在混合长度带来的执行损失，
能否通过分组切分减少该损失，并覆盖第二个 FIA update、重排及结果恢复成本？
不预设 FIA 对混合长度处理低效，也不以改变总工作量证明收益。

## 实验契约

- 保持 Qwen3-4B BF16、Q1、默认 104 桶与固定 56+48 分支。
- 主轨迹仍为 B98/97/103/98；各请求的长度绑定请求身份，不绑定排序后的行号。
- 容量内一半请求长度 128、一半长度 512，以固定种子打乱；实际活跃集合为前 B 个请求。
- 比较 original、length_asc、length_desc 三种顺序，各顺序内 padding 与 split 对称处理。
- 相同 B 的请求集合与总 KV 长度完全相同，dummy 行长度零、slot -1。
- 保存所有计时状态的 metadata，检查逆排列、页表、实际 slot 与总长度。
- 使用原有物理 KV 页，不搬迁历史 KV；长度变化资格检查每次恢复 prefill。
- 每步计算排列、填充输入、上传元数据、全部 FIA update、replay、同步均计时。
- 排序时图内对 hidden/residual 各做一次 index_select 恢复原始顺序，两种策略均承担成本。
- 原 ND eager 参考固定使用原始请求顺序；排序优化必须对该独立顺序参考通过精度检查。
- 固定容量和地址，动态 batch 可以改变排序和逆排列的内容，不重新捕获。
- 六轮等执行次序，每轮 64 步；profiler 与 32 步 phase diagnostics 独立于正式计时。
- 保留同源码等长 KV512 对照；混合长度比等长更快不能解释为切分收益。

这是第一层真实 decoder block 的受控实验，不是完整模型或在线调度。
前缀来自已有 coherent prefill；请求长度在计时中固定，尚不代表连续 KV 增长。
当前使用相同 FIA 实现；分支专用 tiling、算子和设备端任务调度尚未实现。

## 判定规则

先对比同顺序 padding 与切分，再检查分组方案是否优于原始顺序 padding。
若只有排序后的 padding 改善，属于公共排序收益；若 FIA 阶段更快但完整 step 更慢，
不能宣称推理获益。只有稳定完整 block 净收益才扩大验证范围。
若没有明显混合长度损失，停止把单纯长度分组作为主要优化方向。
单个长度分布的负结果不证明所有上下文长度与模型都没有收益。

## 复现

```bash
ASCEND_RT_VISIBLE_DEVICES=0 VLLM_BATCH_INVARIANT=0 \
python benchmarks/multi_graph_bucket_block.py \
  --model /models/Qwen3-4B --nz --native-update --native-replay \
  --static-task-plan --shared-cache --packed-metadata \
  --short-kv-length 128 --request-order length_asc \
  --rounds 6 --repeats 64 --phase-diagnostics --trace \
  --output /tmp/mixed-asc.json
```

将顺序改为 original、length_desc 得到同请求集对照。
去掉两个新参数为等长 KV512 对照。不得覆盖已有报告。

### 128/512 首轮

下表为六轮动态单步 p50 的中位数，正式计时不启用 profiler。

| 顺序 | padding ms | 切分 ms | 切分相对 padding 增时 |
| --- | ---: | ---: | ---: |
| 原始随机请求顺序 | 1.237007 | 1.247545 | 0.85% |
| 短请求优先 | 1.315537 | 1.315062 | -0.04% |
| 长请求优先 | 1.273799 | 1.294932 | 1.66% |

同源码等长 KV512 对照为 1.114387/1.123649 ms，切分慢 0.83%。
该对照使用更简单的原有等长主机准备流程，不能通过与混合路径绝对时间相减，
推导混合长度的设备开销。混合/排序成本应看相同混合请求集合间的对照。

B98 总 KV token 数为 30592；B97 为 30080；B103 为 33152。
每一种顺序均保持请求身份、token、position、物理 KV 页和 slot 相同，
仅改变图内行号并恢复输出顺序；汇总脚本逐项检查该契约。

首轮独立 trace 的 FIA 跨度中位数：原始顺序 padding/split 为 255.75/265.25 us，
短优先为 299.75/292.25 us，长优先为 252.25/270.5 us。
短优先的切分相对同排序 padding 只有局部改善，整步仍比原始顺序 padding 慢。
因此首轮不支持长度排序切分净收益。

为避免只看短 KV 场景，补充 512/2048 的相同比例分布；
128/512 三种顺序按相反进程顺序独立复测：

| 顺序 | padding ms | 切分 ms | 切分相对 padding 增时 |
| --- | ---: | ---: | ---: |
| 原始随机请求顺序 | 1.244262 | 1.259182 | 1.20% |
| 短请求优先 | 1.344458 | 1.348803 | 0.32% |
| 长请求优先 | 1.293794 | 1.301992 | 0.63% |

首轮短优先的约 0.04% 优势没有复现，不构成稳定收益。
排序同时改变页表访问顺序和任务分布，尚不能把设备耗时差异归因于某一个 tiling 机制。

### 更长 KV 测试的内存修正

首次 512/2048 运行在复制全模型 KV 快照时 OOM，尚未进入性能计时。
完整模型 cache 加上所有层的副本超过 64GB；失败报告与日志保留为 long-original。

新增显式 `--snapshot-first-block-only` 选项，仅为本实验使用的第一层 KV 创建快照，
检查所有第一层 cache 均被覆盖。完整模型 prefill 保留，第一层所有请求前缀仍复制初始化，
长度变化资格检查继续恢复该层 KV。全模型/编译实验不能使用这个快照范围。
默认 loader 仍恢复全部层，不改变其它实验。
初始化和 reset 均在正式计时之外，这个修正只改善测试内存，不计作推理收益。
新增 128/512 相同源码对照为 1.231652/1.246167 ms，切分慢 1.18%，与此前方向一致。
继续执行 512/2048 三种顺序；长 KV 命令将长度改为 512/2048，并增加
`--snapshot-first-block-only`。报告中的 `timed_kv_length` 在混合模式指最大分配长度，
真实逐请求长度由 `request_lengths`、`timed_request_metadata` 给出。

### 512/2048 结果与阶段结论

| 顺序 | padding ms | 切分 ms | 切分相对 padding 增时 |
| --- | ---: | ---: | ---: |
| 原始随机请求顺序 | 1.818187 | 1.831894 | 0.75% |
| 短请求优先 | 1.867564 | 1.879719 | 0.65% |
| 长请求优先 | 1.891937 | 1.888024 | -0.21% |

长优先的微小优势没有独立复测，且整步仍慢于原始顺序 padding；不视作有效优化。
原始顺序 trace 中，两路 FIA 重叠中位数约 288.5 us，但自身时长总和约 988 us，
最终跨度约 700.75 us，单路约 688.5 us。实际并发没有缩短关键路径。
这些是分别取中位数的诊断量，不能逐项相加来推算 wall latency。

两种分布都未提供采用简单长度分组的依据。停止扩大排序实验，不接入生产 runner。
不将该结果推广为所有长度分布、模型或专用 kernel 都无收益。
正式数据共十一组 4B 运行、一组 0.6B smoke；另保留一次准备阶段 OOM。
原始数据、trace、源码快照、独立汇总与失败记录在工作区
`outputs/multi_graph_mixed_lengths/`，源代码哈希、同请求集和同 KV 工作量均经离线检查。

## 后续探索方式与候选

按用户 2026-10-17 的反馈，后续探索不每轮跑完整测试矩阵。
先验证一个因果假设，使用一个主样本、必要精度检查和少量无 profiler 计时；
只有出现明显收益信号或准备保留实现时，才扩大复测与回归。

优先候选是两路 FIA 的 host update 真正并行。此前独立流仍在主机顺序调用，
改变 update 顺序已能显著改变启动时序。先以持久 C++ 工作线程、独立 update 流验证
调用是否允许安全并发，以及两个 update 的关键路径能否从串行和接近最长单次耗时。
保留所有 update、ready/completion fence、参数所有权和每步真实长度。
若底层存在全局锁或设备并发仍拖慢，则立即停止，不先整合完整 runner。

较大改造候选是专门为并发设计的 Q1/GQA attention：每个 KV tile 被请求内多个
query heads 复用，任务按 KV 工作量分配，而不是把两个完整 FIA 当作独立黑盒。
这不按 head 拆图。先验证现有 FIA 是否已有同等复用及可量化重复搬运，
没有证据则不重写 kernel；padding 必须同样获得公共 kernel 改进。
另一个算子工程方向是将分支的启动/任务调度合并为单个入口，减少独立管理开销，
但它单独并不能证明切分特有收益，必须由实际更短的执行关键路径验证。
