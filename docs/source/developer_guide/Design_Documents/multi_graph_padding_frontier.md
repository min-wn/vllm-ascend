# 小 Padding 比例下的切分边界

默认 dispatcher 选容量的固定随机样本见[默认捕获档位实验](multi_graph_default_capture_case.md)。
本文容量扫描采用手动容量，两者的实验口径不同。

## 问题与目标

此前 B=129、C=256 的结果不能代表常见容量附近的收益。
本轮固定真实请求数 B=129，缩小 padding 容量到 136、144、160，并补充 129/130 的极小浪费对照。
额外槽位比例定义为 (C-B)/B，假槽位占容量比例则为 (C-B)/C；本文表格使用前者。
每组仍只计时 padding 与切分并行，采用完整 decoder、普通 FIA，保留必要 task update。
环境、测量口径及跨形状精度边界沿用[模型规模实验](multi_graph_model_scaling.md)。

优化目标是使较小浪费比例下仍有稳定收益，而非寻找更大的 padding 容量。
在 4B、B=129、C=136 的约 65 ms replay 上，再降低 1 ms 就相当于约 1.5 个百分点。
应以实际时间判断一项优化是否有效，而非以 stream 数、重叠量或 kernel 数减少判断。

## 当前方案的边界实测

下表使用共享 Dense、每层两路 Attention 后汇合的既有结构，lanes=65+64，KV=512。
每组五轮，每轮三十次，取各轮 wall p50 的中位数；每组包含独立的 padding 对照。

| 模型 | Q | B / C | 额外槽位 | padding ms | 切分并行 ms | 延迟下降 |
| --- | --- | --- | --- | --- | --- | --- |
| Qwen3-4B | 8 | 129 / 129 | 0% | 65.827 | 65.604 | 0.34% |
| Qwen3-4B | 8 | 129 / 130 | 0.78% | 64.057 | 63.577 | 0.75% |
| Qwen3-4B | 8 | 129 / 136 | 5.43% | 65.604 | 63.430 | 3.31% |
| Qwen3-4B | 8 | 129 / 144 | 11.63% | 66.949 | 63.338 | 5.39% |
| Qwen3-4B | 8 | 129 / 160 | 24.03% | 70.845 | 63.336 | 10.60% |
| Qwen3-4B | 8 | 129 / 192 | 48.84% | 85.091 | 63.994 | 24.79% |
| Qwen3-8B | 8 | 129 / 136 | 5.43% | 97.051 | 93.429 | 3.73% |
| Qwen3-8B | 8 | 129 / 144 | 11.63% | 100.087 | 92.172 | 7.91% |
| Qwen3-4B | 1 | 129 / 144 | 11.63% | 32.284 | 30.618 | 5.16% |

在这些固定工作负载中，优势不只出现在接近两倍容量的场景，但小 padding 下收益明显缩小。
0.34% 与 0.75% 不足以认定稳定优势，更不能据此承诺无 padding 时仍胜出。
不同 case 的绝对时间存在波动，也受矩阵尺寸和 kernel 选择影响，不能拟合成严格线性曲线。
本轮部分独立实验在不同物理卡上运行；每组内部的两种模式在同卡交替测量。
跨实验改动必须以同卡复测为依据，不直接用不同卡的绝对延迟证明优化。

## 已实现的结构实验

### 分支后段提前执行

`--split-schedule post-overlap` 保留共享 QKV/RoPE，
每路 Attention 完成后立即执行该路 O 投影、残差归一化和 FFN，
在下一层共享 QKV 前汇合。目标是以不同阶段的重叠减少等待。
新增中间结果写入图内互不重叠的切片，仍每次更新所有 FIA task。
该实验只支持 TP1，避免两条分支同时发起 TP collective。

结果不支持把它作为默认优化：

| 模型与工作量 | lanes | padding ms | 后段提前执行 ms | 相对 padding |
| --- | --- | --- | --- | --- |
| 4B，B129/C144/Q8/KV512 | 65+64 | 68.007 | 72.078 | 慢 5.99% |
| 同上 | 97+32 | 69.745 | 71.528 | 慢 2.56% |
| 8B，B129/C144/Q8/KV512 | 65+64 | 99.823 | 113.762 | 慢 13.96% |
| 4B，B129/C144/Q1/KV512 | 65+64 | 32.518 | 30.653 | 快 5.74% |

Q=1 的切分耗时与原方案 30.618 ms 接近，没有证明进一步改善。
Q=8 的负面结果与拆碎 Dense 矩阵及额外输出拷贝的代价相符；
不能把潜在重叠自动等同于收益。

### 分叉前共享 KV 写入

`--kv-write shared` 将两路 reshape/cache 写入合并为分叉前的一次完整请求写入。
分支只消费已经写入的 KV，仍各自使用真实页表和长度并执行 FIA update。
根流记录的 fork event 覆盖共享写入，两路读取均依赖该 event。

4B、B129/C136/Q8 在同一张卡按 shared/branches/shared/branches 交替独立进程复测：

| 运行 | padding ms | 切分并行 ms | 相对 padding 降幅 |
| --- | --- | --- | --- |
| 共享写入 1 | 66.992 | 64.966 | 3.02% |
| 分支写入 1 | 65.770 | 63.242 | 3.84% |
| 共享写入 2 | 68.068 | 66.054 | 2.96% |
| 分支写入 2 | 65.509 | 63.199 | 3.53% |

共享写入并未改善这组工作负载。Q=1 的单次进程测得 30.379 ms，
相对本进程 padding 32.393 ms 降低 6.22%，但不能据此认定其跨进程稳定优于原方案。
因此保留为显式实验选项，不改变默认分支写入。

## Profile 证据与后续优化方向

4B、B129/C136/Q8 的完整 decoder trace 已出现两路 FIA 重叠，
与此前 0.5B 单层未见重叠的结果不同，不能继续沿用“所有场景均未重叠”的判断。
一个代表样本中：

| 指标 | padding | 两路 Attention |
| --- | --- | --- |
| MatMul kernel 数 | 144 | 144 |
| MatMul 累计 duration | 35.59 ms | 35.37 ms |
| FIA kernel 数 | 36 | 72 |
| FIA 累计 duration | 20.05 ms | 28.23 ms |
| FIA 区间并集 | 20.05 ms | 19.32 ms |
| FIA 重叠区间 | 约 0 | 8.90 ms |

拆成两路后虽有重叠，但累计 FIA 时间上升，最后区间并集只减少约 0.73 ms。
增加的累计时间可能同时来自小 shape 的 kernel 效率与并发资源竞争；
本 trace 没有单独分离这两项因果，不能直接把全部增量归因于资源竞争。
Profiler 会改变 host 提交时序，上述累计 duration 也不能直接相加得到 wall time。

共享 KV 写入的 trace 将 ScatterPaKvCache 次数从 72 降到 36，
代表样本的累计写入 duration 从约 1.77 ms 降到 0.71 ms，
但非 profiler 的 wall time 没有相应改善。
这直接说明少一个 kernel 或更小的累计 duration 并不保证关键路径缩短。

## Attention 执行资源分配：已实现与复测

`--attention-cores N` 让共享 Dense 使用完整资源，
两路 Attention 分别在独立流上限制为 N Cube / 2N Vector，
update 流采用与 capture 相同的限额，以保持 FIA tiling 约束一致。
每层在共享 QKV/RoPE 后分叉，两路完成后汇合，再执行完整批次的 O 投影和 FFN。
该参数限制流可用资源上限，不保证每条流独占一组物理核心。
当前 910B3 设备为 20 Cube / 40 Vector；接口探测、FIA 捕获与 replay 均已实际运行。

N=0 保留原有流结构；N=20 使用与限核实验相同的两个独立 Attention 流，
但每路允许使用全部核心，用于区分流拓扑变化与限额变化。
下表全部为 Qwen3-4B、TP1、B129、Q8、KV512、lanes=65+64，
每个进程内两种模式交替测量五轮，每轮三十次。
C136 各实验在物理卡 0 顺序运行；C130 的两项在物理卡 2 顺序运行。

| 容量 | 每路 Cube / Vector | padding ms | 切分并行 ms | 相对 padding 降幅 |
| --- | --- | --- | --- | --- |
| 136 | 原结构，不限核 | 66.811 | 64.528 | 3.42% |
| 136 | 20 / 40，拓扑对照 | 66.175 | 63.859 | 3.50% |
| 136 | 10 / 20，第一次 | 66.430 | 62.947 | 5.24% |
| 136 | 10 / 20，独立进程复测 | 66.700 | 63.304 | 5.09% |
| 136 | 8 / 16 | 67.788 | 65.280 | 3.70% |
| 130 | 原结构，不限核 | 65.815 | 65.395 | 0.64% |
| 130 | 10 / 20 | 64.108 | 62.707 | 2.19% |

容量 136 的限核结果比原结构多约 1.7 至 1.8 个百分点的收益，
两次独立进程复测接近；全核的拓扑对照没有同等提升。
容量 130 只有 0.78% 额外槽位，限核实验也出现约 2.2% 的降幅，
但该边界每个配置只有一次独立进程测量，尚不足以认定所有近容量负载都稳定占优。
不同进程的 padding 本身会波动，不能直接用跨进程 split 绝对耗时比值宣称优化幅度。
限到 8 Cube 并未进一步改善，说明不能简单假设限额越小越好。
Qwen3-0.6B、B7/C8/Q8 的 10 Cube 实验仍从 padding 5.726 ms 增至 10.019 ms；
该改动没有消除小工作量下的切分固定成本。

限核 trace 的两种模式各包含三个完整 marker，每个 marker 的 MatMul 数为 144，
FIA 数分别为 36 和 72。第一个切分 marker 中，FIA 累计 duration 为 37.47 ms，
区间并集为 19.18 ms，重叠为 18.29 ms。
与前述不限核切分样本相比，重叠显著增多，但 FIA 区间并集只小幅缩短；
限核也使单个 FIA 执行更久。trace 证明执行重叠发生变化，
尚不能将全部 wall time 改善归因于 FIA 或精确分离资源竞争、KV 写入及提交调度的影响。
最终收益以无 profiler 的配对 wall time 为准。

目前限核实验仅完成 TP1 验证；参数仍为显式 benchmark 选项，默认 N=0，
不与后段提前执行组合，也未将其作为生产调度策略或多卡已验证配置。

在此之后，更大的潜在空间是将 Q/K norm、RoPE、KV 写入融合，
以及缩短保留真实长度更新的 host 提交链。两者必须用 trace 确认关键路径占比。
前者需要处理两路页表、slot 和输出别名；后者不能省略 update，
也不能假定 72 次 host 调用的累计时长全部可转化为 wall time 收益。

## 复现与边界

~~~bash
source /etc/profile.d/ascend-multigraph.sh
VLLM_BATCH_INVARIANT=0 ASCEND_RT_VISIBLE_DEVICES=0 \
python benchmarks/multi_graph_model_scaling.py \
  --model /models/Qwen3-4B --batch 129 --capacity 136 --query 8 --kv-length 512 \
  --rounds 5 --repeats 30 --output /workspace/frontier.json
~~~

使用 `--attention-cores 10` 测试限核，`--attention-cores 20` 测试相同流拓扑的全核对照。
使用 `--split-schedule post-overlap` 或 `--kv-write shared` 单独测试其他结构变化。
默认仍为 `joined`、`branches`、`--attention-cores 0`。
这些参数仅扩展基准实验，没有放宽生产准入。
原始报告、trace、对应源码版本和汇总保存在工作区
`outputs/multi_graph_padding_frontier/`。
所有性能结果都保留各自同结构 eager 对照和 changed-input 检查；
跨形状精度、logits、动态长度、在线服务质量仍不在本轮通过范围。

本轮 CPU 相关测试 322 项通过，Qwen3-0.6B 的四种 NPU e2e 配置通过，
包括原结构、后段提前执行、共享 KV 写入和限核。

另有既存 `device_length_decode.py` 的 Triton 导入检查失败；这些不计为已通过。

原始报告的 `script_sha256` 在报告生成时读取磁盘文件。
