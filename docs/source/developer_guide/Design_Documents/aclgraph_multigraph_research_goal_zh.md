# 研究目标：寻找动态形状下多张 ACLGraph 的实际优势

根据用户要求：继续深入思考多图的优势，有完善方案后再深入实施。
日期：2026-10-20。

## 可直接设置的目标

深入研究动态 shape 推理中，多张 ACLGraph 独立调度、并行回放与动态组合能够带来的优势，
形成具有明确瓶颈、完整执行机制和可信收益来源的优化方案，
争取在默认 `cudagraph_capture_sizes` 和常规动态 batch 下，
稳定超过同等优化的 Padding。

先分析已有代码、profiling、历史尝试、论文与技术报告，避免重复失败路线。
重点回答：多图释放了什么调度自由度，缩短哪段关键路径，
为何收益不会被矩阵拆小、额外提交、数据整理、通信和同步抵消；
单图是否可以低成本实现相同效果，多图的必要性在什么条件下成立。
区别于已有工作的机制贡献与实验证据必须作为重点。

形成完善中文方案后先汇报，再开展深入实现。
方案必须包含执行流程、依赖与状态生命周期、多卡通信次序、实际资源与时间成本预算、
适用范围、失败条件及最小验证实验。
优先利用已有时间线；必要时只做能解决关键疑问的小规模 profiling 或接口验证，
不以大量试错代替机制分析。

验证对照至少包括：同等优化的 Padding、多图串行、多图并行、
相同分段与依赖的组合单图。使用默认容量和有代表性的动态 batch，
计入真实长度更新、H2D、拷贝、图提交、状态写回及最终汇合，报告完整 step 的净收益。
不靠专用容量、极端 padding、遗漏工作、切分 attention head 或额外复制模型权重制造优势。
当前聚焦单次 replay，不以推测解码接受率变化解释收益。

大矩阵、算子与通算融合可以作为辅助路线继续，但同样提供给 Padding，单独归因。
优先寻找改变关键路径的结构性优化；若单独的公共优化有更大价值，也应如实说明其定位。
不预设多图必然胜出；尚未找到可信净收益路线时，明确缺口、否决原因和下一项分析，
不把完成文档当成完成性能目标。

## 分阶段交付与实施门槛

1. **证据审查。** 梳理真正独立多图、单图内部多流、请求切分三类工作；
   根据历史结果筛掉已失败、被当前基线覆盖或成本明显过大的机制。
2. **完善方案。** 对有前景的候选给出关键路径图、成本账本、已有工作区别及可证伪预测，
   选出优先路线并先向用户汇报；没有候选通过时，报告分析结论和缺口。
3. **最小验证。** 只验证关键接口、资源窗口和净收益预测；
   多图优于串行但不及 Padding，不能算目标达成。
4. **深入实现。** 机制和最小验证通过后，再扩大真实模型与动态轨迹接入，
   检查正确性、稳定性和端到端表现。

固定调度可能由组合单图表达，不能把多个 graph handle 本身写成原创性。
若价值来自有限捕获预算下的动态组合，应先证明有用方案随动态状态改变，
再用实际图资源与回放成本证明预算优势，分别归因适应性和并行收益。
若组合单图能达到相同表现，应明确真正的贡献是分段依赖或调度机制。

## 当前起点

目前没有已证实可大幅、稳定超过强 Padding 基线的独立多图方案。
