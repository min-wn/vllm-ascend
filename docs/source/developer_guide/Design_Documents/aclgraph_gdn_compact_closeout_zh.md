# GDN compact Q1/Q4 部署扩展：最终收口结论

日期：2026-10-22。状态：**正式结束，不再追加接入优化实验。**

本文件是当前执行边界。历史文档的条件性候选资格、runner接入计划和补救设想均为阶段记录，不再作为待办。冻结实现、原始结果、失败日志、阈值和来源SHA全部保留；不修改内核、状态ABI或精度，不追加性能、质量或接入实验，不继续排查stream、不做dense/compact桥接，不围绕现有compact寻找补救路线。

## 一、已经验证的机制

1. **请求组ready流水有可单独消融的调度贡献。** 在相同compact算法、算术、分组和20 AIC/40 AIV资源下，Cube每组产品就绪后允许配对AIV消费，并用consumed背压保持生命周期；delayed等本生产者的局部整批产品完成。两者共享延迟提交、投影/TP/MLP重叠和最终join，因此这些共有能力不能再次计入ready的独立收益。
2. **收益不只依赖compact这一状态表示。** 保留环形日志、动态游标和前置周期flush的ReplaySSM FP32日志变体，在已有A2同算法delayed/ready对照中也观察到净收益。但该FP32变体不是社区原配置，不能称为优于社区最佳；原BF16激活＋FP16日志失败继续保留。
3. **Q1/Q4共用compact状态的有限契约成立。** 当前query长度与前一步接受长度分开表达；支持四种Q1/Q4切换、请求重排、暂停恢复，同一owner连续使用base/log，模式切换不经dense导出再导入。真实完整层补充验证了conv前缀接受语义及接受4后纯Q1；不同有限filler不影响有效输出、逻辑conv历史和接受态。
4. **同算法调度正确性通过相应边界的检查。** delayed/ready的输出、日志、状态推进与终末提交一致；完整层审计与eager/graph检查通过。这不等于compact与官方算法数值等价，也不授予任务质量或部署资格。

生产消费流水、checkpoint加日志、动态接受前缀和延迟物化均有已有工作基础。可辨认的工程成果限于已记录的A2请求组映射、发布/背压协议及其同源消融；不是新的状态算法，也没有证明切分或多图独享优势。

## 二、保留的ready收益及准确边界

| 已有证据 | 结果 | 必须保留的限制 |
| --- | --- | --- |
| ReplaySSM FP32日志单层机制对照 | 六轮改善4.30%～7.40%，逐轮百分比均值5.53% | 相同A2移植算法的调度对照；不是社区原精度配置，也不是社区最佳性能对比。 |
| 真实激活单层动态范围 | compact中/高负载平均改善3.12%/5.30%；低负载0.43%且存在负轮次 | 40步闭合轨迹、有限负载；不是全负载保证。 |
| 原Q4 128步decoder＋final norm回放 | 约4.80%闭合改善，3/3轮为正 | 同一计时进程内三轮；不含LM head、draft、采样或服务，不能称跨进程稳定整网加速。 |
| 含BF16 head的固定轨迹完整模型执行回放 | 原Q4/低/中负载闭合均值改善4.55%/1.70%/3.13% | 每档两对独立进程；执行固定token/接受轨迹，没有真实draft、采样或服务调度。 |
| 离线真实自回归生成 | 同compact算法、强制Q4、BF16 head下，生成循环平均改善2.6687%，三对均正 | 按9970个真实循环输出token计量；不是在线服务吞吐，也不是相对官方算法的收益。 |

离线生成的含prefill、一次导入及终末提交的批次阶段合计均值改善1.373%，但三对分别为−2.882%、+2.475%、+4.314%，**稳定完整批次净收益未成立**。该合计也是分阶段成本之和，不是连续冷启动请求wall time。旧4.80%、含head回放和2.67%来自不同端点与负载，不能混成同一个加速率。

这些结果保留为受限执行机制和消融证据，**不表述为官方替代、生产可用或服务加速**。

## 三、没有达到的目标

- **数值与质量准入没有恢复。** 原0.5% hidden NRMSE筛选失败；真实文本平均KL、TV P99及最差owner ΔNLL超出冻结预算。AIME26一次配对中官方26/30、compact23/30，已有具体任务退化记录。样本范围有限，不宣称普遍退化同样幅度，但也不能宣布无损。第28题后续head诊断的局部积极结果不覆盖这些失败。
- **Q1/Q4完整GDN层净收益没有保留。** recurrence对称out/out约2.29%的收益通过过当时门槛，但完整层稳定退化，不能外推到完整模型或实际生成。
- **原生runner兼容性和部署资格未获得。** 既有原生探针在默认图捕获时stream资源耗尽，实际生成step为零；Q1/Q4数量和head行数的原生规则分析属于旧ledger结合源码的条件重建，不是原生生成观测。动态request/owner、状态槽释放复用及实际runner生命周期未接入。
- **没有服务收益、普遍负载优势或切分必要性结论。** 未取得在线TTFT、TPOT、尾延迟、吞吐与调度干扰下的部署证据；ready可由单图或Padding使用，不能将其包装成切分独有收益。

上述目标没有达到的结论与已成立的ready机制证据并存，不用其中一项替代另一项。

## 四、完整层退化的已知成本

对象为Qwen3.5-27B TP2的单个GDN decoder layer 4，56 owners、固定224行共同dense容量，冻结16步（10个Q1-only、6个mixed）。两侧共同dense投影、norm、TP、残差和MLP实现及形状一致。输入是同文16-token prefill初态配官方layers0～3逐步生成的真实激活，明确标为**新构造的teacher-forced层级对照**，不是原ledger第54步完整状态恢复，也不是自回归生成。

两个独立性能进程交换顺序，每配置8个正式完整链样本；保留64条rank原始样本，按同identity取生命周期较大rank的整条记录。32条主样本合并中位数为：

| 完整16步生命周期 | 强制Q4 ready | Q1/Q4 ready |
| --- | ---: | ---: |
| 中位数 ms | 41.037764 | 47.093439 |

Q1/Q4增加6.055675 ms，耗时增加14.7563%；两个独立进程分别退化14.5150%和14.8249%，噪声门槛0.279721%。完整成本包含一次导入、入口准备/上传、完整层执行、状态更新、最终等待及终末物化，未删除失败或离群样本。

另行事件诊断的两进程均值如下；每格为对应分段的端点和（ms），**不是正式wall的精确分解**：

| 分段 | 准备端点增量 | 图内层执行端点增量 | 总端点增量 |
| --- | ---: | ---: | ---: |
| Q1-only，10步 | +3.341500 | +0.630660 | +3.972160 |
| mixed，6步 | +1.913430 | +0.527830 | +2.441260 |
| 16步诊断合计 | +5.254930 | +1.158490 | +6.413420 |

源码可确认Q1/Q4额外增加每步pack/inverse/packed-active三个小描述符上传，共3,808 bytes/step、16步48次；图内增加三份投影后输入的index_select/mask、输出清零和逆映射。强制Q4没有支付不用的三个描述符上传；共同层不再加入此前五份recurrence输入的fixture重建。

准备端点含CPU构造、主机提交、H2D和设备等待主机的空隙；图内端点含所有层计算及新增适配。**二者均退化，与适配抵消潜在节省一致，不能只用共同dense计算稀释解释；尚未隔离单项贡献。** 不能把5.254930 ms全称作copy时间，不能把诊断增量加到正式wall，也不能由行数减少推导时延收益。

## 五、仍未解决但不再追查的问题

- CPU元数据构造、每次小上传的提交/同步、设备空隙以及pack/mask/逆映射各自的独占成本没有分离；未证明某个小工程修复足以挽回净收益。
- 原ready机制的精确Cube/AIV指令交集、独占等待与握手开销未完全隔离；不能把PMU标量时间全部当作可删同步预算。
- compact相对官方的实际设备舍入差异、后续BF16网络及head的放大关系没有形成能恢复整体质量资格的有限修复；这些诊断保持结束。
- 原生runner实际生成负载分布、动态槽复用和线上服务收益未验证；不以旧ledger条件重建补足这些证据。

这些是证据覆盖边界，**不是继续实验的任务清单**。不以“可能合并上传”“也许改布局或桥接”继续当前路线。

## 六、未来重新选题的起点

本轮不启动新选题。未来若另行授权，先从能够实际完成短文本生成的**原生runner＋官方算法基线**出发：冻结版本、精度、默认图目录与真实工作负载；记录真实query、draft、接受、filler、图padding与请求生命周期；用profile和干净端点定位实际关键路径上的重复或等待成本，并量化可消除预算，再决定是否开发候选。

没有可复现官方基线，先解决基线可运行性；没有足够且可处理的瓶颈预算，就不开发。新方向不预设必须复用compact、强制Q4、双状态桥接或现有内核，也不以补救本路线为目标。本轮没有运行新的原生探针、性能轮次、任务评测或候选搜索。
