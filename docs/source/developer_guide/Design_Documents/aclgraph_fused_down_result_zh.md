# 保留大矩阵的 Down 通算融合：接口资格与局部收益

更新日期：2026-10-20。

## 本轮结论

当前 A2/910B3、现有驱动和 CANN 组合，已实测通过
`npu_mm_reduce_scatter_base(..., comm_mode="aiv")` 的 BF16/NZ eager 执行、
手工 ACLGraph 捕获和改变输入后的重复回放。
无需更新驱动即可继续研究这一具体接口；不能据此推断所有 MC2 接口都兼容。

把普通 Down GEMM＋AllReduce，替换为融合 GEMM/ReduceScatter＋AllGather，
在恢复完整输出以后，局部设备端点仍有约 13.8%～15.7% 的观测改善。
这比上一轮只调整 152+152 为 128+176 的尺寸筛选更值得进入真实层验证。
但它是公开融合能力的收益，**不是已经证明切分优于 Padding，更不是完整模型加速结果**。

## 测了什么，为什么端点等价

模型维度来自 Qwen3.5-27B TP2 的 Down：
每个 rank 的输入 `[M,8704]`、本地权重 `[5120,8704]`，
最终每个 rank 都必须拿到完整归约后的 `[M,5120]` 输出。

| 对照 | 图内路径 | 最终输出 |
| --- | --- | --- |
| 普通 AR | 输入刷新 → 大 GEMM → AllReduce | 两卡均持有完整输出 |
| 普通 RS/AG | 输入刷新 → 大 GEMM → ReduceScatter → AllGather | 两卡均持有完整输出 |
| 融合 RS/AG | 输入刷新 → 融合大 GEMM/ReduceScatter → AllGather | 两卡均持有完整输出 |

ReduceScatter 的行划分是两卡各持有 M/2 行；没有按 head 切分，也没有复制 attention 权重。
三组都使用同一份本地 NZ 权重。恢复完整输出的 AllGather 和最后的计算流等待均计入。
普通 RS/AG 是因果对照：它能分开“换了通信分解方式”和“使用融合实现”的影响。

输入准备的 CPU 随机数生成和计时前 H2D 不计入；图内 source→input 刷新计入。
没有 Norm、FIA/update、GDN 状态、其他层、logits、采样或服务请求。
不能把它描述为完整 decoder 或端到端推理测试。

## 结果

每个条件五轮，轮间交替三种模式顺序；每模式每轮两个预热、六个正式样本。
每个样本先取两卡较慢的设备时间和墙钟时间，再汇总中位数。
下表的百分比只使用各自同轮实验里的普通 AR 作基线。

| 条件 | 普通 AR 设备 μs | 普通 RS/AG 设备 μs | 融合 RS/AG 设备 μs | 设备改善 | 墙钟改善 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 默认容量 400，随机权重 | 481.02 | 488.89 | 405.34 | 15.73% | 12.50% |
| 默认容量 304，真实第 3 层 Down 权重 | 374.89 | 382.98 | 323.11 | 13.81% | 10.92% |

容量 400 的五轮设备改善分别为 16.69%、15.07%、15.60%、13.90%、17.97%。
容量 304 的五轮设备改善分别为 15.62%、14.60%、11.60%、13.29%、14.02%。
两次实验各自五轮设备和墙钟中位数均改善；这仍是小范围局部证据，不是置信区间或普遍保证。
两个容量的权重条件不同，不能把它们相减来单独归因 batch 大小。

容量 304 的权重直接读取 checkpoint 的
`model.language_model.layers.3.mlp.down_proj.weight`，
rank0 取原矩阵第 0～8703 列，rank1 取 8704～17407 列，保留原 BF16。
两个 TP 分片分别保存字节哈希；输入仍是受控随机数据，没有真实上游激活。
两种容量都来自已有实验保存的官方默认图表，没有新增专用容量。
本轮各容量分别启动，尚未验证同一进程在这两个容量之间切换图池。

## 正确性和时间线核查

每种模式用两组不同输入进行 eager 对照，并在同一捕获图上改变输入后回放。
同模式 eager/replay 输出逐元素完全一致；输出有限，最后两组无效 Q4 请求保持零。
所有融合结果与普通 AR 均通过 `atol=0.02, rtol=0.02` 的局部阈值。
真实权重条件下，两组输入的 NRMSE 约为 0.00659% 和 0.00586%，最大绝对差均为 0.03125。
这些数字不证明模型质量准入，也不消除此前切分与 Padding 的完整模型数值差异。

十二份 trace 核对了三类工作量：
普通 AR 有一个 GEMM 和一次 AllReduce；普通 RS/AG 有一个 GEMM、一次 RS 和一次 AG；
融合路径有一个 `MatmulReduceScatterV2` 和一次 AG。
分析器同时检查矩阵计算所在流确实等待最终 collective 完成，避免提前停止端点计时。

profiler 对这些短算子的耗时干扰明显，例如融合 kernel 在 trace 内会比无 profiler 端点更长。
所以时间线只用于核对路径、恢复输出和最终等待，性能数字全部来自独立无 profiler 计时。
当前 trace 没有导出融合 kernel 内部的块级生产/通信时间，
不能把全部收益定量归为内部重叠，也不能声称已获得外部可用的行级完成事件。

结果保存的是按源码在进程内汇总后的慢 rank 配对样本；各 rank 汇总前的原始计时未单独保存。
两份 rank 报告的配对样本一致，分析器核对完整五轮三模式样本格、来源哈希和 trace 哈希。
该记录限制需保留，不能声称可从存档重新计算单 rank 的全部原始计时。
探针已为后续运行增加原始 rank 样本保存；这不会补回本轮未保存的数据。

## 与已有工作和切分主线的关系

这次没有发明 GEMM/ReduceScatter 融合。安装包已有接口，仓库也已有
`MatmulReduceScatterFusionPass` 和默认 AIV 设备包装。
新增的是在当前机器、真实 Down 权重、默认容量及手工 ACLGraph 下的执行资格和闭合端点证据。
它补上了此前“接口存在，但当前驱动/图模式未验证”的缺口。

因此应先把这种能力作为 Padding 与切分都能使用的公共基线，不能只给切分启用。
当前两次实验都没有切分提前消费控制组，不能计算“切分独有收益”。
融合 AllReduce 和 AllGather/Matmul 等其他接口未在本轮运行，
也没有证明当前路径是所有公开融合实现中最快的。

后续切分机制仍要回答一个额外问题：
能否让某些完整请求行保留归属、先做局部工作，减少等待全批就绪，
同时保留大矩阵效率并超过同等融合的 Padding。
这一方向与序列并行、通算融合已有研究相关；单独使用这些算子不构成新方法。
可研究部分是固定图容量下动态请求身份、状态归属、合并位置与跨步生命周期的联合约束。

## 下一阶段：先接真实相邻层，不直接扩到全模型

第一步将融合 Down 接入一对真实相邻 FIA/GDN 层，保持最终 hidden、residual 和状态端点一致。
普通 Padding、融合 Padding、普通切分和融合切分需要同轮比较，
继续保留相同分块但禁止提前消费的因果对照；不增加 capture sizes。
FIA 的真实长度 update、状态提交及最终等待继续计入。

这一步重点看两件事：公共融合在真实激活下是否仍有收益，
以及 AIV 融合是否与已经并行的 GDN 状态提交争用资源。
局部独立算子的空闲资源条件不能代表全模型。
如果融合 Padding 获益而切分没有额外收益，就保留公共优化，明确收缩切分贡献。

只有闭合两层仍有收益，才扩大到完整模型，不能直接把单边界节省乘 64 层。
如果后续改为 RS 后保留请求行归属，再接局部 Norm 与 AllGather/GEMM，
必须同时处理 residual 的行归属并计入其恢复成本。
仅省去 hidden 的 AllGather、把 residual 恢复遗漏在计时外，是无效比较。
普通融合 kernel 的未完成输出仍然不可读取。
