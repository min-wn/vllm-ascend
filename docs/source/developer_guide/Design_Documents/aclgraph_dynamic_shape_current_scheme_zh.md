## 1. 主线与既有方案的关系

当前主线是文首的局部请求提前消费与 core 前合并，用于掩盖 TP 通信。
下面的设备端注意力计划是之前已实施的独立路线，保留为背景和对照，
不能将它提供给 Padding 也能获得的收益归因于请求切分。

此前的一条路线从“把一个批次切成多张图并行执行”，转为：
**在默认填充图机制下，由设备端真实描述符产生共享的原生注意力计划，
再通过完整请求/注意力头归属改善注意力调度与执行。**

二者都服务于动态形状推理，但属于不同层次的优化：

| 层次 | 优化对象 | 当前状态 |
| --- | --- | --- |
| 图层 | 将动态批次分成多个已有图，并用多流并行回放 | 前期探索方向；当前结果不证明其优于填充。 |
| 计划层 | 根据每步真实长度和页表，决定各核承担哪些注意力工作 | 当前已实现受条件保护的完整请求/头归属原生策略。 |
| 算子层 | 改善同一核内部的分块、累加和数据搬运 | running-O 反向配对未复现稳定收益；MM2 单 V 缓冲的宽搬运版本两种顺序均退化，均未推广。 |

当前仍保留默认图捕获容量列表，图执行完整的合法填充容量。
没有为某个测试批次增加专用容量，也没有通过删除物理填充制造优势。
未来如果重新比较切分和填充，双方必须使用同样最优、合法的注意力
计划和执行算子，才能把收益归因于切分。

## 2. 为什么固定图仍需要每步真实信息

ACLGraph 固定的是算子结构、缓冲区地址及允许的物理形状。
每步实际请求数、KV 长度、请求归属和缓存页路由仍可能变化。
只保留一个固定形状，并不能让注意力忽略这些变化。

以当前测试的 Q4 为例，每个请求有四个查询词元。
原始 B98 记录映射到物理容量 400，即 100 个物理请求位置；
B128 映射到容量 512，即 128 个位置。
这里的 400/512 是物理词元数，不是请求数。
填充位置的 KV 长度为零，注意力必须真实写出零结果。

因此，方案区分两类信息：

- **图的静态容量**：沿用默认桶，保持捕获地址、物理范围和图生命周期稳定。
- **当前精确描述符**：保留真实 KV 长度、Q 边界和页表，不能用桶上限替代。

旧版 FIA 路径依赖的真实主机端长度更新仍必须执行。
我们没有以省略必要更新的方式测量旧版。
sink 路径则把真实长度交给设备端原生计划生成器，每次回放都重新生成计划；
必要的描述符准备、主机到设备复制（H2D）、计划生成和最终同步都计入当前完整耗时。

## 3. 已实现的执行链

当前实验的一步可概括为：

```text
本步真实请求、KV长度、页表
        │
        ▼
固定地址描述符填充及必要H2D
        │
        ▼
图内原生 AICPU 计划生成器：根据当前描述符重建计划
        │
        ▼
稳定的int32[1024]原生计划
        │
        ├── 注意力调用 0：私有Q/K/V与工作区
        ├── 注意力调用 1：私有Q/K/V与工作区
        ├── ...
        └── 注意力调用 15：私有Q/K/V与工作区
        │
        ▼
全部执行完成及最终汇合等待
```

十六次注意力顺序执行，共享兼容的只读计划。
这不是十六个流并行，也不意味着共享权重、KV 内容或可变工作区。
共享计划的前提是这些算子调用的长度、页路由语义和几何配置相容。

当前已验证目标是 A2 路径上的 BF16/TND、Q4、Q12/KV2、D256、page128、
稀疏模式 3，使用实际 20 个 Cube/40 个 Vector 核限制。
为适配 D256，隔离包缩小了 MM1/MM2 的子块并增加容量检查，保留原 L1 布局。
这属于具体目标的工程适配，不等于官方已全面支持所有 D256 组合。

### 完整请求/头归属策略具体改变什么

上游计划生成器已有代价估计和切分搜索，并能把一个注意力头的 KV 工作拆给多个核，
之后通过 FlashDecode（FD）归并部分结果。

我们的策略把完整的 `(request, KV head)` 作为不可再拆的工作单元。
它沿用原生代价权重，在连续的工作单元序列上做最小化最大负载分段：
目标是尽量降低最重核的估计工作量，然后输出合法的原生端点。
构造的新候选将 FD 和归并字段置零，完整覆盖所有物理位置；
不满足几何、容量或端点合法性时，回退到上游策略。

这带来一个可利用的条件：同一个请求/注意力头的累加生命周期可以归属同一核。
代价是完整注意力头无法继续拆小，长请求可能使负载更难均衡。
现有完整请求/头归属与禁用 FD 同时变化，当前结果不能单独证明收益全部来自取消 FD。

**当前计划生成器每次都完整重建计划，不是增量计划维护。**
已有 Python 增量原型只是 CPU 假设验证：高归并代价下，127 个后续步
中有 126 个回退，且 Python 路径慢于其完整重建对照。
该负面结果保留，没有接入原生 NPU 计划生成器。

## 4. 现有性能证据究竟到哪一层

目前实验使用十六组私有、固定、驻留的合成 Q/K/V。
动态轨迹改变真实描述符和页路由，但没有加载完整模型，
没有根据模型输出生成新 Q/K/V，也没有持续写入真实生成词元的 KV。
因此，下表是 **注意力链** 的结果。

| 实验 | 完整头策略相对上游策略的结果 | 可以支持的结论 |
| --- | --- | --- |
| 第6阶段：四条固定记录 | 完整耗时均值下降 5.665%；有一轮退化 | 小范围策略收益存在，不能代表完整动态轨迹。 |

第7阶段保留了全部 3072 次计时和 1536 对匹配样本。
四轮均值降幅为 1.957489%、2.083247%、**-0.117017%** 和 3.269628%。
整体 P99 从 6.550212 ms 增加到 6.631752 ms。
四轮中一轮变慢，尾延迟也变差，不能只报告均值收益。

第7阶段的独立正确性阶段通过 2048 个步骤检查和 6144 个 FP32 抽样行比较，
最大绝对误差为 0.0003158003091812134。
这是独立资格验证阶段的抽样，不是对每个计时回放的逐元素验证。

未使用的图没有额外回放；144 个 FP32 抽样行通过，全部 80 次计时保留。
每个组合仅一个独立新进程，进程顺序、时段、设备状态和分配位置仍然混杂。
因此不能说“更多图更快”，也不能确认回放历史就是收益差异的原因。
动态证据仍以第7阶段的 1.788171% 为准。

这些结果目前都不支持以下结论：

- 已取得完整模型端到端或在线服务吞吐收益。
- 切分并行优于默认填充。
- 已实现原生增量计划、通用多流调度或独属于切分的新算法。
- 只要使用 Q4 或更大模型，就能稳定复现较大的点测收益。

## 5. 为什么下一步改注意力执行算子

当前诊断已经把目标缩小到算子执行内部。
独立性能剖析记录的十六次注意力内核总时长如下：

| 物理容量 | 完整头策略比旧版多用的内核时间 | sink 内核之间的间隙总和 | 完整头策略计划生成器时间 |
| --- | ---: | ---: | ---: |
| 400 | 269.705 µs，慢 7.675% | 37.711 µs | 74.128 µs |
| 512 | 370.147 µs，慢 8.226% | 37.444 µs | 112.112 µs |

计划生成器、间隙、内核和主机端区间可能重叠，不能相加重建完整耗时。
上表也不保证所有差额都能消除：旧版和 sink 的实现及分块配置不同。
但它说明继续削减算子启动间隙的预算较小，执行算子内部更值得做源码消融。

小规模硬件计数器进一步发现，完整头策略相对旧版的 Vector 标量流水线、AIC MTE2
和结果搬运流水线（fixpipe）时间增加，比 MAC 时间增加更明显。
这只是定位线索；流水线可以并发，不能把这些时间相加，
也不能据此认定 HBM 带宽饱和或承诺某个可回收百分比。

### 下一项源码消融：减少 running-O 往返

源码位置是固定版本 `bec19b8dea1e` 的
`fia_block_vec_nonquant_sink.h::DealBmm2ResBaseBlock`。
现有路径每个 S2 分块读取新的 MM2 部分结果；非首块还要从 GM 工作区
读回上一块的 running-O，做缩放和相加；非末块再通过 UB 中转复制写回 GM。
running-O 就是在线 softmax 过程中持续更新的输出累加值。

有两个可独立验证的修改：

1. **先去除中间 UB 中转复制**：仍保留 GM 累加，只检查多余复制能否安全移除。
   必须等待 MTE3 完成，保证输入缓冲在搬运结束前不被复用。
2. **再尝试 running-O 在 UB 驻留**：以完整注意力头的生命周期为单位，
   减少跨 S2 的 GM 读回和写回，保留 MM2 的既有工作区交接。

目前优先实施第二项；去中转复制仍是未实施的备选消融。
running-O 补丁和隔离构建工具已实现；两记录结果及复现限制见本节后半部分，
尚不能把它计入完整动态轨迹或模型收益。
受限实现解决以下约束：

- Q4/GQA6 对应 24 行，现有两侧 AIV 按 16/8 行分工；
  D256 的 FP32 累加器分别需要 16/8 KiB，不能按 12/12 行估算。
- 三任务缓存中的 Vec2 实际按创建顺序串行消费，S2 是最内层。
  因此独立于 Vec1 的一个累加器足够；补丁仍检查注意力头身份、循环连续性、
  AIV 行区间及首末块，防止读取未初始化状态。
- 原静态 UB 为 184 KiB/AIV。把 outputQue1 从 32 KiB 缩到 16 KiB，
  再分配独立 16 KiB 累加区，总量保持 184 KiB。
  Vec1 的 BF16 输出最多 16 KiB，最终 BF16 输出最多 8 KiB；
  缩容模式中，回退路径的 FP32 中转区限制为 16 行，最多 16 KiB。
- 非末块删掉原输出队列和 GM 写回后，显式保留 V→MTE3 依赖，
  防止原跨核完成信号过早释放 MM2 工作区。
- 不改变 softmax 递推、真实长度、页路由、MM2 交接和最终输出格式。
  FD、容量或生命周期不满足要求时保留原路。

快路径目前仅限定 A2、BF16/TND/page128、Q12/KV2、D256、max-S1=4、
preload=2、S2 块不超过 512、无 sink/RoPE 的组合。
这里的 max-S1=4 是计划中的单请求 Q 上限，物理词元容量仍为 400/512。
不满足静态条件的形状保留原 32 KiB 队列和工作区路径；
FD 等不满足任务条件的注意力头继续走工作区。
合法且保持注意力头形状的状态失配会先同步溢出写回到原工作区后回退；
这不保证违反原生接口约束的描述符在注意力头中途改变 Q/M 形状仍然安全。

源码补丁以完整 SHA 和匹配锚点拒绝版本漂移，并支持同源宏 0/1 对照。
构建工具只在新实验目录编译一个 BF16 二进制文件，给上游策略/完整头策略两种计划生成器
装入同一执行算子，不安装系统包，也不修改既有算子包。
本轮小实验只编译目标路径的 `104000000010222223` 和
`104000000010322223` 两个分块配置键，并严格核对产物中的键集合。
这是受限实验二进制文件；源码保留回退路径不代表该二进制文件包含其他形状所需的模板。
完整头策略计划中的 FD 注意力头数可以为零，但主机端仍可能选用支持 FD 的模板，
因此不能根据策略名字删除该编译变体。
源码、CPU 测试和静态预算通过并不等于设备正确性或性能通过。

**资格按实际计划和生命周期判断，不能按 `whole` 策略名字判断。**
如果上游策略计划也满足条件，必须获得同一执行算子快路径。
实验需要分别看执行算子收益、原生调度收益及二者的交互，
避免把只给完整头策略使用的算子优化误报为完整头策略调度优势。

先用原 B98/B128 两条记录做小实验，保留全部计时前后正确性门槛和完整耗时，
性能剖析与计时分开。只有端点收益与相关执行证据一致，才扩大动态验证。

交接关键路径，再决定是否值得做同步与分块大改，而不是继续为此补丁扩展性能矩阵。

### 搬运与计算分块解耦：设备筛选未通过

源码核查发现，D256 的 MM2 为保护 L0B 容量而采用 64 行计算分块，
同时把 L1 搬运也绑定为 64 行。本轮尝试将两个 32 KiB 的 V 槽位合为一个
64 KiB 槽位，一次搬入 128 行，内部仍按原顺序计算两次 64 行。
L1 总量、必要数据量和计算量不变；代价是减少一个轮换缓冲。
源码推导的搬运批次减少约 48%，但设备对照的中位耗时增加约 3.4%～4.0%。
基线→候选与候选→基线的均值均退化；其中一个候选进程有尖峰，全部样本保留。
80 次计时、144 行 FP32 抽样和 24 次完整计划检查完成，四个进程的完整输出哈希相同。
因此不采用此变体，不扩大完整轨迹或模型矩阵。

这属于填充和多图切分都可使用的共同算子优化，不证明图切分的必要性。
搬运分组与槽位数同时改变，不能把退化全部归因于失去双缓冲。
下一项已实现受几何条件保护的 Q/V 布局：两槽 Q 各从 96 KiB 缩为 64 KiB，
两槽 V 各从 32 KiB 扩为 64 KiB，L1 总量不变。布局在分配前选择，
不合格几何同时恢复原 Q/V 分配和步长，保留槽位数与事件协议。
原生地址与计算顺序检查、两个受限分块键的隔离编译和六进程筛选均完成。
相同新布局下，扩大搬运分组的均值耗时改善约 1.34%～4.52%；
但相对真正原布局，四组中位数改善仅为 0.968%、0.164%、0.440%、−0.726%，
单独剖析的注意力总耗时均未改善。新布局控制组本身存在代价，
不能把相对它的收益当作相对原实现的净收益。
120 次计时、216 行 FP32 抽样和 36 次完整计划核对通过，完整输出哈希一致。
因此保留三组消融证据，不替换原布局，不扩大该候选的完整轨迹或模型矩阵。
已按此收紧方向，实现保留原布局的跨块预取补丁：
在当前块矩阵乘发起后、Cube 屏障前，预取当前任务的下一块 P/V。
保持 64 行搬运和计算、原槽位释放、必要更新及端点等待。
原生完整方法的 CPU 协议检查和同布局四进程对照已完成。
两个容量在正反顺序均退化，端点均值慢约 1.94%～4.49%，
单独注意力剖析同样退化；完整输出哈希一致。
因此不推广该候选，不扩大完整矩阵。
另两个硬件指标诊断进程已完成：原版 MTE2 活跃比例约 81%～86%、标量约 59%～62%，
候选 MAC 时间基本不变，但标量活动每次注意力增加约 5.69～6.26 µs，搬运时间未下降。
这些是全注意力聚合指标，不能相加为开销，也不证明 MM2 的具体根因。
同一任务内 V 页地址复用已实现并完成四进程对照，两个容量正反顺序均退化，
均值慢约 0.57%～3.49%；完整输出哈希一致，故不推广。
另外完成设备 sink 与真实 TP-local FFN 权重的独立输入并行小实验，
两进程中位耗时改善约 5.58%/6.50%。追加消融显示，只隐藏计划就有约 4.78% 改善，
计划先完成后的计算并行仅约 2.00%，且只有一个进程。
不能把原局部差值全部归因于资源互补；实验不含模型依赖或 TP 通信，
也不是同批请求切分与 Padding 的对照。
下一候选为设备任务计划与请求块就绪调度，保留大 GEMM 效率；
先查真实关键路径预算与有界就绪协议，不把普通双流直接扩展全模型。
详细结果和大收益主线的门槛见
[页地址消融与就绪调度候选](aclgraph_sink_overlap_mainline_zh.md)。
停止继续枚举槽位大小。
这仍是共同算子优化，没有新增完整模型或切分独有收益结论。
详细机制、源码工作量、负结果和准入门槛见
[搬运与计算分块解耦](aclgraph_fia_sink_mm2_transfer_zh.md)及
[双 V 缓冲实验](aclgraph_fia_sink_mm2_double_buffer_zh.md)。
跨块预取的边界与验证安排见
[MM2 跨块预取实验](aclgraph_fia_sink_mm2_prefetch_zh.md)。

## 6. 与已有工作的区别，以及毕设能写什么

下表依据仓库已有的来源核查记录，详细源码锚点见
[贡献边界审计](aclgraph_fia_sink_contribution_scope.md)。
本文没有开展新的全面查新，也不据此声称研究优先权。

| 已有工作或机制 | 我们复用的内容 | 目前可以明确区分的实现 |
| --- | --- | --- |
| 官方 FIA sink PR 15336 | 设备真实长度、AICPU 规划/执行分离机制、1024 字 ABI、兼容层共享计划、原生代价搜索与 FD | A2 D256 适配；完整请求/注意力头的连续最小化最大负载策略；合法端点输出与回退。 |
| FlashInfer 规划/执行分离机制与注意力调度 | 规划与执行分离、跨兼容层复用计划属于已有原则 | 当前使用 A2 AICPU 计划生成器和既有端点 ABI；不是算子内部票据分发调度。 |
| FlashInfer 均衡 GQA 等设备调度 | 设备长度驱动、拆分长请求及归并已有先例 | 当前限定 A2/D256/GQA6/page128，采用完整有序请求/注意力头；硬件差异本身不证明算法新颖。 |
| 在线 softmax 与片上输出累加 | 递推累加和保留片上中间值是已有注意力方法 | 待验证的是与原生完整注意力头归属、UB 容量和在途任务生命周期结合的受保护实现。 |
| 固定图池、固定缓冲和默认桶调度 | 属于图推理基础设施 | 当前贡献是具体适配和可复核实验，不是发明固定地址或填充图。 |

当前毕设可以扎实描述三部分：

1. **问题与约束**：动态真实长度、固定图容量、原生 ABI、A2 片上存储与流水线
   生命周期之间的关系，以及为何不能省略必要更新或随意添加容量。
2. **已实现机制**：受条件保护的完整请求/头归属原生调度、D256 适配、严格覆盖与回退。
   完整注意力头所有权如何改变 FD 与负载均衡，是可解释的机制差异。
3. **证据与边界**：相同执行算子对照、包含真实计划生成开销的端点、
   默认桶动态轨迹、正确性抽样、独立审计、负轮次和 P99 退化。

下一阶段可以继续检验“调度归属与执行算子数据驻留的联合设计”。
其价值必须来自与上游同等执行算子优化后的比较，不能把既有片上累加方法本身
写成首创。此前小实验观察到的有限执行算子改善未通过反向配对复现，
新的 MM2 搬运变体也未通过筛选，尚不足以形成稳定联合优势或毕设级新颖性结论。
后续优先检验能体现切分必要性的执行机会，也允许有足够收益的独立优化单独成立。
共同算子优化不能写成切分独有优势，切分与填充应使用同等优化后的算子。

## 7. 从当前小实验到完整模型的门槛

顺序是先验证执行算子修改，再判断是否值得接完整模型，避免立即扩大模型矩阵。
若小实验有效，仍需要保留原 17 桶和捕获顺序，区分时间顺序回放历史与
进程/设备波动；两条记录的较大收益不能直接带入完整动态轨迹。

完整模型接入已有 [第8阶段协议](aclgraph_fia_sink_stage8_protocol.md)，目前只是协议，
没有实施模型 sink 适配器，也没有第8阶段 NPU 结果。
计划在 Qwen3.5-27B TP2 的真实 QKV、KV 写入、GDN 状态、残差和通信路径上，
依次验证：

- 三个原始步骤的真实模型正确性与关键路径预算。
- 一次完整 128 步连续状态资格验证。
- 通过前两项后，再做正式的三对照性能实验。

三对照必须分开解释：

| 对照差值 | 实际回答的问题 |
| --- | --- |
| `legacy_pad` → `upstream_sink_pad` | 采用设备计划/共享计划等既有 sink 机制的整体影响。 |
| `upstream_sink_pad` → `whole_sink_pad` | 同一 sink 执行算子下，原生调度策略的独立影响。 |
| 将来的填充 → 切分 | 双方拿到同样最优方案后，切分本身是否仍有收益。 |

真实模型端点必须计入必要准备、真实 KV 写入、计划生成器、输出适配、TP 通信及
最终汇合等待。注意力链的 89.354 µs 不能直接乘到模型层数，
也不能把当前注意力耗时降幅称作完整推理加速。
若真实关键路径可暴露的收益不足，应报告预算限制并停止扩大该路线的性能矩阵。
