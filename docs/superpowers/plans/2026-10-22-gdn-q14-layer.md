# Q1/Q4 共用 compact 状态：有界完整层验证计划

本计划落实本轮用户规格，计时前冻结范围与判据。使用 systematic-debugging 核查状态语义，使用 writing-plans 记录执行步骤；已有原型与历史失败不改写。

## 目标与边界

- Qwen3.5-27B 原权重、TP2、decoder layer 4、BF16 层计算与 FP32 compact 状态。
- 主比较为原强制 Q4 ready 与 Q1/Q4 ready；内核、状态 ABI、20 AIC/40 AIV 和接受轨迹不变。
- 原 ledger 54～69 的 16 步、56 owners、224 行共同 dense 容量；不新增图 bucket。
- 保存资料缺少 ledger step54 的层 hidden/residual、conv 和 SSM 张量。因此使用同文 16 token prefill 和官方 layers0～3 逐步重算的新构造 teacher-forced 层级对照，不能称原 ledger 激活重放。
- 两侧共同 dense 投影、norm、输出投影、TP、残差与 MLP 形状均为 224 行。Q1/Q4 所需核心打包/还原及元数据上传计入执行成本。
- 不接 runner，不跑整网或新质量评测，不修改内核；无可辨收益即结束本轮扩展。

## 执行顺序

1. 核查 installed GDN/conv 的版本与实际文件，保存源码及内核二进制 SHA。conv 通过前一步接受长度在同一物理槽内选历史；全 Q1 不得丢失此 selector。
2. 新增独立输入 helper，构造匹配的 conv/SSM prefill 初态与每步变化的真实层输入。当前 quartet 从该 owner 已接受文本位置开始；暂停 owner 的位置不变。来源、token 与张量 hash 单列。
3. 新增 benchmark-only core adapter。沿用官方 spec varlen conv，显式表达当前 Q1/Q4 与前一步接受长度；冻结内核仅替换 recurrence backend。保持默认容量224，固定地址元数据。
4. 在设备上先做接受1、接受4、Q4→Q1→Q4、重排、暂停恢复及有限 filler 干预。比较有效层输出、合法日志、接受态、下一步逻辑 conv 历史与终末物化；不要求两侧无效 conv 候选尾部相同。
5. 审计 eager/graph、delayed/ready 同算法一致性及16步连续状态。正确性未通过则不计正式性能。
6. 两个独立 TP2 性能进程，进程0强制Q4→Q1/Q4，进程1反序。每配置2轮链预热、8个完整16步正式样本。禁止 profiler/逐张量下载/逐步落盘进入正式计时。
7. 成本表分别列初始化导入、执行链、终末物化及合计；Q1-only/mixed 用另行事件端点分解解释，主判据只使用无插桩完整链 wall time。
8. 原始证据、中文报告及根目录 md/txt 保存后定向验证、独立复核、签名提交并推送当前分支。根据结果收口，不自动展开下一阶段。

## 冻结的完整层准入标准

两个独立进程的 lifecycle 中位数改善均须为正。合并样本中位数改善须超过噪声阈值：两倍的以下量最大值——两配置各自跨进程中位数相对跨度、两配置各自样本 MAD/median。所有样本保留，合计必须等于初始化+执行+终末，不删除离群样本。不强制复现 recurrence 的2.29%，不以减少行数代替测量。

共同输入生成、模型加载、静态分配、预热和图捕获在正式计时外，分别记录。每条链从共同合法初态独立推进；执行包含入口输入复制、CPU 元数据/索引构造、必要上传、core打包、完整层与commit、最终等待。初始化包括导入和清零；终末包括按最终接受长度提交SSM并提取逻辑conv历史及完成等待。
