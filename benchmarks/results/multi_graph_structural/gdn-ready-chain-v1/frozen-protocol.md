# GDN 请求组 ready：含 BF16 head 的完整执行回放

本轮只验证同一 compact FP32 算法的调度收益。保留全部既有数值和质量失败；不再开展 AIME、首次分歧诊断或 FP32 head 优化。下面的协议在查看本轮性能结果之前冻结。

## 冻结对象与输入

- Qwen3.5-27B 原权重、TP2、910B3；48 个 GDN 层、16 个 FIA 层、final norm 和原 BF16 LM head。
- 同一 compact FP32 状态表示与内核二进制。delayed/ready 只改变请求组产品的发布时机，其余计算、核数、工作区和图配置一致。
- 原 Q4 128 步轨迹保持原样，SHA256 为 `0519bc80410bd15d0893e0283189425ec285d53003198c163183b79e6249e524`。
- 另复用既有 low、medium 各 40 步的请求、长度、接受前缀序列，包含请求重排和暂停恢复。仍保留整网 fixture 的 128 个驻留 owner，其余 owner 休眠，初始 prefix 为 16。
- 两档范围使用原整网 fixture 的确定性随机词表 token，**不是**此前单层真实文本激活。与此前单层实验的直接差异包括：64 层、默认图目录和输入激活。两种调度内部输入完全相同。
- 只使用本机 EngineArgs 自动生成的默认图目录，每步由原 dispatcher 选择容量；不新增 bucket，不固定定制容量，不新增路由器。

## 完整成本口径

执行阶段包含每步 token 构造与上传、host 元数据生成与必要上传、16 个 FIA 图更新、完整 decoder、final norm、BF16 全词表投影与 TP gather、状态更新和最终等待。head 对该默认容量下全部 Q4 行（含 padding 行）投影，两种调度一致。没有采样、draft 生成或服务调度；本结果只能称为**固定轨迹的完整模型执行回放**。

一次初始化为共同真实 prefill 后的 compact 状态转换与工作区准备，沿用既有 fixture 端点。它不等于模型加载或服务冷启动。终末物化包括所有驻留 owner 的最终接受前缀构造、上传、物化和等待，并保留卷积及 FIA 历史。终末接受前缀沿用各冻结轨迹定义。

每个 TP rank 分别记录执行、一次初始化、终末物化与合计。以合计最慢的同一个 rank 提取全部成本列，确保表内闭合。模型加载、共同 prefill、capture、正确性下载与 fixture 恢复均在计时之外，另外记录。

## 进程隔离与正确性

每档两对，共 12 个独立 TP2 进程组，顺序为 delayed→ready、ready→delayed。全部顺序运行，不并行计时。每进程在正式计时前做一次不计时的连续轨迹回归，保存每步完整 hidden、residual、logits 的字节 SHA，以及初态、终末全部 SSM、staging、卷积、FIA 与 host 生命周期契约 SHA。

计时后完整终态必须与该进程不计时终态相同，再逐 rank 跨进程核对两种调度的每步输出和初末状态。只核对同一算法的调度一致性，不重做官方/compact 的跨算法精度评测。未通过一致性或未闭合的运行保留为失败，不能用于收益结论。

两个独立配对只能给出首轮复现和波动范围，不宣称普遍稳定或生产收益。初始化耗时分别实测，不沿用旧常数。旧约 4.80% 不含 head，不能移植到本轮。

## profile 与停止边界

只有某一负载两对都获得闭合净收益，才选择该负载的少量代表 step，单独运行 delayed/ready profile。无 profile 的计时结果与 profile 样本严格分开。

首先使用本机 CANN/torch_npu 时间线和 PipeUtilization 计数，拆分 GDN mixed kernel、提交、投影、FIA、TP、上传和 host 等待。Cube/AIV 管线利用率不能直接冒充真实时间交集；如数据不足以量化组内等待与重叠，必须明确可测边界，必要的诊断插桩另存，不能替换本轮计时的冻结库。

首轮交付完整成本表、负载收益表和关键路径解释。发现明确主要瓶颈后才提出下一项性能修改，不在本轮枚举内核微调，不扩大负载、模型或质量评测。
